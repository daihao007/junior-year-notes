# 一、语义分析的概念（10.1，P3～7）

1. **上下文有关分析**：主要是标识符作用域、名字引用与声明之间的关系。
2. **类型的一致性检查**：例如参与运算的操作数类型是否匹配、赋值两侧类型是否相容。
3. **语义处理**：
   - 声明语句：其语义是声明变量的类型等。语义分析程序主要做**填符号表、登录名字的特征信息、分配存储**。
   - 执行语句：其语义是要做某种操作。语义处理的任务是根据操作的目标结构生成**中间代码或目标代码**。

上下文无关文法能描述程序的语法结构，但不能单靠文法解决全部语义问题。例如内外层程序块都出现标识符 `I` 时，究竟引用哪个 `I`，需要考虑作用域。改用上下文有关文法虽然能够描述某些限制，但构造、分析都比较复杂，实际编译器通常在上下文无关语法分析的基础上加入**专门的语义动作**，借助符号表完成检查。

本章约定（P2）：

- 源语言：通用过程语言；目标代码：**栈式抽象机的伪汇编程序**。
- 翻译方法：**自顶向下的属性翻译**。
- 语法成分翻译子程序：**继承属性**作为值形参，**综合属性**作为变量形参。
- 语义动作子程序：继承属性作为值形参，综合属性通过 `RETURN` 作为返回值。
- ATG（属性翻译文法）：在文法产生式中插入语义动作，并在语法成分、动作之间传递属性。`↑` 表示综合属性，`↓` 表示继承属性，`@` 表示语义动作。

# 二、栈式抽象机及其汇编指令（10.2，P8～14）

栈式抽象机：由**三个存储器、一个指令寄存器和多个地址寄存器**组成。

- **数据存储器**：存放 AR（活动记录）的运行栈，还有堆、常量区等。
- **操作存储器**：操作数栈，放表达式操作数、部分计算结果，也用于调用时加载实参和返回地址。
- **指令存储器**：存放程序指令（P-code 等）。

常见寄存器（P9）：`PC` 指向当前指令；`BP` 指向活动记录基址；`SP` 与运行栈栈顶有关；`NP` 与堆空间边界有关。**本章后续的操作数栈与动态运行栈分开考虑**（P39、P75）。

## 2.1 基本指令（P11～13）

| 指令 | 含义 |
| --- | --- |
| `LOD D` | 把地址 `D` 所在单元的**内容**压入操作数栈 |
| `LDC c` | 把立即常量 `c` 压栈 |
| `LDA (D)` | 把变量 `D` 的**地址**压栈 |
| `STO D` | 把栈顶内容存入变量 `D` |
| `ST @D` | 把栈顶内容存入 `D` 所指向的单元（间接存储） |
| `STN` | 把栈顶内容写入**次栈顶所指的单元** |
| `ADD` | 次栈顶与栈顶相加，结果留在栈顶 |
| `SUB` | 次栈顶减栈顶，结果留在栈顶 |
| `MUL` | 次栈顶与栈顶相乘，结果留在栈顶 |
| `EQL`、`NEQ` | 等于、不等于比较，结果为 `1` 或 `0` |
| `GRT`、`LES` | 大于、小于比较 |
| `GTE`、`LSE` | 大于等于、小于等于比较 |
| `AND`、`ORL`、`NOT` | 逻辑与、或、非 |
| `JSR lab` | 转入过程 `lab`，本章约定先把返回地址压入操作数栈 |
| `ALC M` | 在运行栈分配大小为 `M` 的活动记录空间 |

注意 `LDA` 和 `LOD`：前者取**地址**，后者取**值**。这在赋值、数组引用和传参中反复出现。

## 2.2 赋值代码举例（P11、P14）

对 `a := b + c;` 生成：

```text
LDA (a)
LOD b
LOD c
ADD
STN
```

操作数栈（以下用 `[...]` 表示，右侧为栈顶）：

```text
LDA (a)  -> [&a]
LOD b    -> [&a, b]
LOD c    -> [&a, b, c]
ADD      -> [&a, b+c]
STN      -> []          把 b+c 存入地址 &a
```

# 三、声明的处理（10.3，P15～38）

**语义的表示**：给出语言结构的属性翻译文法来说明其语义及语义动作，并把语义动作插入属性翻译文法产生式的适当位置。

**编译程序处理声明语句的任务**：

1. 分离出每一个被声明的实体，并把名字填入符号表。
2. 把被声明实体的有关特征信息尽可能多地填入符号表。

**对于已声明的实体，在处理引用时**：

1. 检查引用（种类、类型等）是否正确。
2. 根据类型、目标代码地址等特征信息，生成相应目标代码。

因此：**声明主要做填表（填表前先查重），引用主要做查表**（P16）。

## 3.1 声明的两种方式（P17～20）

1. **类型说明符放在变量前面**，如 C 语言 `int a;`：填表时已知变量名和类型，可直接填入符号表。
2. **类型说明符放在变量后面**，如课件中的 PL/1 风格 `DECLARE(X, Y(N), YTOTAL) FLOAT;`：先登记名字，后面读到类型，再对之前的符号表项**反填**类型。

普通文法：

```text
<declaration> -> DECLARE '(' <entity list> ')' <type>
<entity list> -> <entity name>
               | <entity name> ',' <entity list>
<type>        -> FIXED | FLOAT | CHAR
```

对应 ATG（省略部分终结符上的属性）：

```text
<declaration> -> DECLARE @dec_on↑x '(' <entity list> ')' <type>↑t @fix_up↓x,t
<entity list> -> <entity name>↑n @name_def↓n
               | <entity name>↑n ',' @name_def↓n <entity list>
<type>↑t      -> FIXED↑t | FLOAT↑t | CHAR↑t
```

三个动作：

- `@dec_on↑x`：记录符号表当前下一个可用表项的**入口地址/下标** `x`。
- `@name_def↓n`：将读到的名字依次填入从 `x` 起的符号表项；需要内部指针或计数器指向下一空闲表项。
- `@fix_up↓x,t`：读到类型后，把类型 `t` 反填到从 `x` 开始的本次声明对应表项中。

**反填**：先预留位置或登记尚不完整的信息，等后面的信息确定后，回过头修改原先位置。P20 的 `DECLARE(A,B,C) FLOAT` 可以理解为先建立 A/B/C 表项，最后一起填 `FLOAT`。

## 3.2 常量类型声明（10.3.1，P21～22）

例子：`constant integer SYMBSIZE := 1024;`

```text
<const del> -> constant <type>↑t <entity>↑n := <const expr>↑c,s @insert↓t,n,c,s ;
<type>↑t    -> real↑t | integer↑t | string↑t
<const expr>↑c,s -> <integer const>↑c,s | <real const>↑c,s | <string const>↑c,s
```

属性含义：`t` 为声明类型，`n` 为常量名，`c` 为常量值，`s` 为常量表达式的类型。

对例子有：`t=integer`、`n=SYMBSIZE`、`c=1024`、`s=integer`。

`@insert`：

1. 检查 `t` 与 `s` 是否一致，不一致则报错。
2. 将常量名、类型和值写入全局符号表。

## 3.3 简单变量声明（10.3.2，P23～25）

```text
<svar del> -> <type>↑t,i <entity>↑n @svardef↓t,i,n @allocsv↓i ;
<type>↑t,i -> real↑t,i | integer↑t,i
            | character↑t '(' <number>↑i ')'
            | logical↑t,i
```

- `n`：变量名；`t`：类型；`i`：该类型变量需要的数据空间大小。
- 例：`real x;`、`integer j;`、`character(20) s;`。

`@svardef`：调用符号表插入函数，把 `n,t,i` 填表；若重名则报错，若符号表溢出则终止编译。

```text
procedure svardef(t, i, n);
    j := tableinsert(n, t, i);
    if j = 0 then errmsg(duplicate, statementno);
    else if j = -1 then begin
        errmsg(tblovflow, statementno);
        abort;
    end;
end;
```

`@allocsv↓i`：为简单变量分配数据空间，课件示意为 `codeptr := codeptr + i`，其中 `codeptr` 为地址区指针；该动作与 `@svardef` 可以合并。

对变长字符串等可变大小的数据实体，往往需要在**堆**中动态分配实际数据空间，并用指针引用；指针及必要的长度信息可记录到符号表中（P25）。

## 3.4 数组变量声明（10.3.3，P26～38）

### 3.4.1 静态数组、动态数组与行优先存储（P26～27）

- **静态数组**：数组大小编译时已知，可在编译时建立完整的**数组模板（数组信息向量）**。
- **动态/变界数组**：大小到运行时才能确定，编译时可以确定模板所需的空间，但模板中的部分内容需运行时填入。
- 课件假设大多数语言采用**按行优先存储**：最后一维下标变化最快；课件特别指出 FORTRAN 按列优先存储。

例：`array B(N, -2:1) char;`，默认第一维下界为 1，第二维下标为 `-2,-1,0,1`。存储顺序：

```text
B(1,-2), B(1,-1), B(1,0), B(1,1),
B(2,-2), B(2,-1), B(2,0), B(2,1), ...
```

`LOC` 是**数组第一个元素的地址**，即 `B(1,-2)` 的地址，不是模板地址。

### 3.4.2 n 维数组元素地址计算（P28～30）

各维下界、上界分别为 $L(i),U(i)$；访问元素下标为 $V(i)$；元素占 $E$ 字节。

$$
\boxed{ADR=LOC+\sum_{i=1}^{n}[V(i)-L(i)]P(i)E}
$$

其中：

$$
P(i)=\begin{cases}
1,&i=n,\\[4pt]
\displaystyle\prod_{j=i+1}^{n}[U(j)-L(j)+1],&1\le i<n.
\end{cases}
$$

**$P(i)$ 的含义**：第 $i$ 维下标加 1，在行优先存储下要跨过的**元素个数**，等于其后所有维度长度的乘积。

例如二维数组 `B(N,-2:1)`：

$$
P(1)=1-(-2)+1=4,\qquad P(2)=1
$$

把公式中的下界部分合并成不变部分：

$$
\boxed{RC=-\sum_{i=1}^{n}L(i)P(i)E}
$$

于是：

$$
\boxed{ADR=LOC+RC+\sum_{i=1}^{n}V(i)P(i)E}
$$

- **LOC**：数组首元素的数据区地址。
- **RC**：地址计算中的**不变修正项**，用于消去各维下界的影响。
- **可变部分**：$\sum V(i)P(i)E$，依赖本次访问下标。

P30 示例令 `N=3`，访问 `B(2,1)`，得到：

$$
RC=-[1\times4+(-2)\times1]E=-2E
$$

$$
ADR=LOC-2E+(2\times4+1\times1)E=LOC+7E
$$

当 `char` 占 1 字节时即 `LOC+7`。课件 P32 的模板表直接写 `RC=-2`，可理解为本例以元素单位（或 $E=1$）记录的修正值；计算实际字节地址时要保持单位一致。

### 3.4.3 数组模板（P31～33）

作用：**计算下标变量地址、检查下标是否越界**。

模板自上而下按课件排列：

```text
U(n)
L(n)
P(n)
 ...
U(1)
L(1)
P(1)
n
RC
```

模板大小：

$$
\boxed{3n+2\text{ 个存储单元}}
$$

无论常界数组还是变界数组，**维数确定后模板空间大小在编译时就可以确定**；常界数组模板可在编译期构造，变界数组需生成在运行时构造模板的代码。

课件 P32 的 `array B(3,-2:1) char` 模板：

| 字段 | 值 |
| --- | ---: |
| U(2) | 1 |
| L(2) | -2 |
| P(2) | 1 |
| U(1) | 3 |
| L(1) | 1 |
| P(1) | 4 |
| n | 2 |
| RC | -2 |

### 3.4.4 数组声明的 ATG 文法（P34～38）

输入文法：

```text
<array del> -> array <entity> '(' <sublist> ')' <type>
<sublist>   -> <subscript> | <subscript> ',' <sublist>
<subscript> -> <integer expr> | <integer expr> ':' <integer expr>
```

ATG（保留课件中的动作名 `@bannds`、`@dimen#`）：

```text
<array del> -> array↑k @init↑j <entity>↑n '(' <sublist>↑j ')'
               <type>↑t @symbinsert↓j,n,t,k

<sublist>↑j -> <subscript> @dimen#↑j
              | <subscript> ',' <sublist>↑j @dimen#↑j

<subscript> -> <integer expr>↑u @bannds↓u
             | <integer expr>↑l ':' @lowerbnd↓l
               <integer expr>↑u @upperbnd↓u,l
```

属性含义：`k` 为数组标志，`n` 为数组名称，`t` 为元素类型，`j` 为维数计数结果，`l/u` 为某一维的下界/上界值。

动作程序（P36～38）：

1. `@init`：`p := p+2; j := 0;`，在模板区**预留 RC 与 n 的两个单元**，并清零维数计数器 `j`。
2. `@dimen#`：`j := j+1`，统计数组维数。由于 `<sublist>` 采用右递归，相关动作在递归返回时执行。
3. `@bannds↓u`：当前维只写上界时，令 $U(i)=u$，隐含下界 $L(i)=1$，并处理 $P(i)$。
4. `@lowerbnd↓l`：记录 $L(i)=l$。
5. `@upperbnd↓u,l`：记录 $U(i)=u$，并处理 $P(i)$。
6. `@symbinsert↓j,n,t,k`：将数组名、维数、元素类型、数组标志填入符号表，为数组分配数据区。

**为什么 $P(i)$ 需要反填？**

$$
P(i)=[U(i+1)-L(i+1)+1]P(i+1)
$$

第 $i$ 维的系数依赖**后面一维**的信息；按从左到右识别时，先处理前一维未必能立即得出 $P(i)$，所以要等后面维度的信息得到后反填。

对于**变界数组**（P38），动作还需生成运行时代码：记录各维上下界，计算并保存 $P(i)$；`@symbinsert` 还要生成调用运行子程序的代码，以计算 RC、确定数组数据区大小、分配空间，并把数据区首地址记入符号表。上述是动作要完成的功能，课件没有列出这些动作的完整内部实现。

# 四、表达式的处理（10.4，P39～56）

表达式处理的主要任务：**生成计算表达式值的代码**。操作数先用加载指令压到操作数栈，算术/逻辑指令从栈顶取操作数，计算结果继续留在栈顶。本章的操作数栈与用于动态存储分配的运行栈分开考虑。

## 4.1 基本整型表达式的 ATG（P40～43）

```text
<expression> -> <expr>
<expr>       -> <term> <terms>
<terms>      -> ε
              | '+' <term> @add <terms>
              | '-' <term> @sub <terms>
<term>       -> <factor> <factors>
<factors>    -> ε
              | '*' <factor> @mul <factors>
              | '/' <factor> @div <factors>
<factor>     -> <variable>↑n @lookup↓n↑j @push↓j
              | <integer>↑i @pushi↓i
              | '(' <expr> ')'
```

- 把加减放在 `<terms>`，乘除放在 `<factors>`，使乘除优先级高于加减。
- `@lookup↓n↑j`：根据名字查符号表，得到表项下标 `j`；未找到则报错。
- `@push↓j`：`emit('LOD', symbtbl(j).objaddr)`，加载变量值。
- `@pushi↓i`：`emit('LDC', i)`，加载整型常量。
- `@add/@sub/@mul/@div`：生成对应算术指令；动作必须在右操作数处理完后执行。

例：`x+y*3`（P41～43）

```text
LOD x
LOD y
LDC 3
MUL
ADD
```

操作数栈先形成 `y*3`，再与 `x` 相加。**看到 ATG 时，既要能识别文法产生式，也要会按动作出现的位置写出指令顺序。**

## 4.2 混合类型表达式：属性传递和转换（P44～48）

P40 的简单文法忽略操作数类型，且变量只考虑简单变量。P45 在此基础上允许**整型、实型混合运算**，并继续扩展到数组元素。

类型属性 ATG 的核心部分：

```text
<expression>    -> <expr>↑t
<expr>↑t        -> <term>↑s <terms>↓s↑t
<terms>↓s↑u    -> @echo↓s↑u
                | '+' <term>↑t @add↓t,s↑v <terms>↓v↑u
                | '-' <term>↑t @sub↓t,s↑v <terms>↓v↑u
<term>↑u        -> <factor>↑s <factors>↓s↑u
<factors>↓s↑u  -> @echo↓s↑u
                | '*' <factor>↑t @mul↓t,s↑v <factors>↓v↑u
                | '/' <factor>↑t @div↓t,s↑v <factors>↓v↑u
<factor>↑t      -> <variable>↑i @type↓i↑t
                | <integer>↑i @pushi↓i↑t
                | <real>↑r @pushi↓r↑t
```

理解属性：

- `<term>↑s` 得到当前项类型，`<terms>↓s` 把已知类型传给后续部分。
- `@add↓t,s↑v` 接收两个操作数类型，必要时生成转换指令并返回**运算结果类型** `v`。
- `@echo↓s↑u` 只是将已有类型传回：`u := s`。
- **同一条产生式中复用的字母是相连的属性变量**；不同产生式内部都叫 `t`，不代表它们必须有同一个具体值。

P48 的 `@add` 举例：如果运算一侧为 `integer`、另一侧为 `real`，则生成类型转换指令，把整数转换成实数，再 `emit('ADD')` 并返回 `real`。课件分别使用 `CVN` / `CNV` 表示次栈顶/栈顶的数值转换（应以 PPT 上对栈位置的说明为准）。

## 4.3 数组元素作为表达式中的变量（P49～55）

简单变量与数组元素对应不同的生成过程：

```text
<variable>↑j -> <identifier>↑n @lookup↓n↑j @push↓j
              | <identifier>↑n @lookup↓n↑j
                '(' @template↓j↑k <sublist>↓k,j ')'

<sublist>↓k,j -> <subscript>↑t @offset↓k,t↑i <subscripts>↓i,j
<subscripts>↓k,j -> @checkdim↓k,j
                  | ',' <subscript>↑t @offset↓k,t↑i <subscripts>↓i,j
<subscript>↑t -> <expr>↑t
```

几个动作的功能：

| 动作 | 功能/生成的指令 |
| --- | --- |
| `@lookup` | 查标识符是否定义，取得它在符号表的入口位置 `j` |
| `@template↓j↑k` | 生成 `TMP`，把数组**模板地址**压栈，初始化下标计数器 `k=0` |
| `@offset↓k,t↑i` | `k:=k+1`；检查下标表达式类型必须为整型；生成 `OFS, k`；返回处理后的维数 |
| `@checkdim↓k,j` | 若处理的下标个数 `k` 与符号表记录的维数不同则报错；一致则生成 `ARR`、`DER` |

P50～52 的伪代码核心：

```text
procedure template(j);
    emit('TMP', symbtbl(j).objaddr);
    k := 0;
    return(k);
end;

procedure offset(k, t);
    k := k+1;
    if t <> 'integer' then 报错：数组下标应为整型;
    else emit('OFS', k);
    return(k);
end;

procedure checkdim(k, j);
    if k <> symbtbl(j).dim then 报错：数组维数与声明不匹配;
    else begin
        emit('ARR');
        emit('DER');
    end;
end;
```

`OFS` 在运行时负责下标越界检查，并**递推计算地址公式的可变部分**（P54）：

$$
VP(0)=0,\qquad VP(k)=VP(k-1)+V(k)P(k)\quad(1\le k\le n)
$$

在课件 `char` 例子（元素占 1 字节）中：

$$
ADR=LOC+RC+VP(n)
$$

若用一般的字节单位，须与第 3.4.2 节中 `RC`、`E` 的约定保持一致。

P55 示例：`array B(3,-2:1) char;`，访问 `B(2,1)`：

```text
TMP        取得数组模板地址
第 1 个下标 2 → OFS 1，VP(1)=0+2*4=8
第 2 个下标 1 → OFS 2，VP(2)=8+1*1=9
ARR        形成元素地址 LOC+(-2)+9=LOC+7
DER        根据地址取出 B(2,1) 的值
```

注意：**`ARR` 产生数组元素的地址，`DER` 再加载数组元素的内容**。二者不能混淆。

## 4.4 逻辑表达式（P56）

逻辑表达式与算术表达式类似，先加载操作数并计算，再通过比较/逻辑指令得到真假值。

课件例子为 `~(x=y & y≠z | z<x)`：

```text
LOD x
LOD y
EQL
LOD y
LOD z
NEQ
AND
LOD z
LOD x
LES
ORL
NOT
```

比较指令生成 `0/1`，`AND/ORL/NOT` 进一步组合结果。

# 五、赋值语句的处理（10.5，P57）

例：`X := Y + X;`

对应目标代码：

```text
LDA (ll,on)x
LOD (ll,on)y
LOD (ll,on)x
ADD
STN
```

**左值/右值**：赋值号左侧需要变量的**存储地址**，右侧表达式需要变量的**内容**。因此同一个 `X` 在赋值号两侧分别使用 `LDA` 和 `LOD`。

ATG（P57）：

```text
<assignstat> -> @setL↑L <variable>↓L↑t :=
                @resetL↑L <expr>↑s @storin↓t,s ;
```

动作功能：

- `@setL`：`return(true)`，设置左值标志 `L=true`，指示后续变量处理取地址。
- `<variable>↓L↑t`：根据左值标志生成合适的代码，并返回被赋变量类型 `t`。
- `@resetL`：`return(false)`，切换到右值处理，指示右侧表达式取变量值。
- `<expr>↑s`：生成右侧表达式求值代码，返回结果类型 `s`。
- `@storin↓t,s`：若 `t` 与 `s` 不一致，按允许的规则生成类型转换代码；最后 `emit('STN')` 完成赋值。

`STN` 执行前操作数栈典型状态：`[目标地址, 表达式结果]`，把结果写入目标地址。

# 六、控制语句的处理（10.6，P58～69）

核心是**标号与跳转指令的生成**。要区分：

- `genlab`：产生新标号（名字）。
- `emit('JMF',lab)`、`emit('JMP',lab)`：生成引用该标号的转移指令。
- `setlab(lab)`：将标号放到当前目标代码位置。

## 6.1 if 语句（10.6.1，P58～62）

### （1）基本控制流

只有 `IF ... THEN ...`：

```text
计算 log_expr
JMF labA          条件为假时跳到 labA
THEN 部分代码
labA:
```

有 `IF ... THEN ... ELSE ...`：

```text
计算 log_expr
JMF labA
THEN 部分代码
JMP labB          THEN 执行完后跳过 ELSE
labA:
ELSE 部分代码
labB:
```

`JMF` 是**条件为假时转移**，`JMP` 是**无条件转移**。`labA` 是 ELSE 入口（或无 ELSE 时的结束位置），`labB` 是整个 IF-ELSE 的出口。

### （2）if 的 ATG 文法

```text
<if_stat>   -> <if_head>↑y <if_tail>↓y
<if_head>↑y -> IF <log_expr> @brf↑y THEN <stat_list>
<if_tail>↓y -> @labprod↓y
              | ELSE @br↑z @labprod↓y <stat_list> @labprod↓z
```

- `@brf↑y`：`labx:=genlab; emit('JMF',labx); return(labx)`。生成条件为假时的跳转，并返回标号 `y`。
- `@br↑z`：`labz:=genlab; emit('JMP',labz); return(labz)`。生成无条件跳转（跳过 ELSE），并返回标号 `z`。
- `@labprod↓标号`：执行 `setlab(标号)`，把标号设置到当前目标程序位置。

属性传递：`<if_head>↑y` 先产生需要跳转到的标号，`<if_tail>↓y` 接收并在相应位置安放这个标号。**为什么动作不能乱放**：`@brf` 必须在条件计算后，`@br` 必须放在 THEN 部分后面，`@labprod↓y` 放在 ELSE 部分前面。

## 6.2 for 循环（10.6.4，P63～69）

课件例子：

```text
for i := 1 to n by z do
    <statement>
    ...
end for;
```

含义：初始化循环变量、按步长更新、判断是否超过上界，循环执行语句体。**按这份 PPT 的例子，首次进入循环体前并不先进行上界判断**；P64 采用先跳入 `start`，执行循环体，再进入更新/判断部分的流程。负步长或初值超界等一般情况未在这一例中展开。

### （1）ATG 文法

```text
<for loop> -> <for head>↑a,f,r <rest of loop>↓a,f,r

<for head>↑a,f,r -> for <id>↑a := <expr> @initload↑s
                    to @labgen↑r <expr> by
                    @loadid↓a <expr> @compare↓a,s↑f

<rest of loop>↓a,f,r -> do <stat_list> end for
                        @retbranch↓r @labemit↓f
```

属性：

| 属性 | 含义 |
| --- | --- |
| `a` | 循环变量的地址 |
| `s` | 循环体入口标号 `start` |
| `r` | 循环更新/判断位置标号 `loop` |
| `f` | 循环结束位置标号 `end_loop` |

### （2）P64 目标代码框架（按课件示意）

```text
LDA (i)
LOD (expr1)       给 i 赋初值
STN
JMP start        第一次直接进入循环体

loop:
    LOD (expr2)  加载上界
    LOD (i)      加载当前循环变量
    LOD (expr3)  加载步长
    ADD          计算 i+步长
    STO (i)      更新 i
    BGT end_loop 超过上界则退出

start:
    <statement>
    ...
    JMP loop     回到更新/比较处

end_loop:
```

P64 图中 `LOD(expr1)` 是表示加载**初值表达式的结果**；如果它是立即常量 `1`，实际使用相应的常量加载指令。`BGT` 及栈中操作数的具体约定以这台课件抽象机为准。

### （3）P65～69 语义动作

| 动作 | 主要功能 |
| --- | --- |
| `@initload↑s` | 生成循环变量赋初值的代码（P63）；结合 P64 的目标序列安排首次跳至 `start` |
| `@labgen↑r` | `r:=genlab; setlab(r); return(r)`，在当前位置设置 `loop` 标号 |
| `@loadid↓a` | `emit('LOD',a)`，加载循环变量当前值 |
| `@compare↓a,s↑f` | 生成 `ADD`、`STO a` 更新循环变量；生成 `BGT f`；设置 `start` 标号 `s`；返回结束标号 `f` |
| `@retbranch↓r` | 循环体结束后生成 `JMP r` 返回 `loop` |
| `@labemit↓f` | 设置循环出口标号 `f`，P68 也写作 `@labprod` |

`@compare` 的课件伪代码：

```text
procedure compare(a, s);
    emit('ADD');
    emit('STO', a);
    f := genlab;
    emit('BGT', f);
    setlab(s);
    return(f);
end;
```

关键是把三个标号分开：**`start` 是循环体，`loop` 是更新/判断，`end_loop` 是退出位置**。初次执行 `JMP start`；循环体末尾 `JMP loop`；若未触发 `BGT`，顺序进入 `start` 再执行循环体。

# 七、过程调用和返回（10.7，P70～81）

## 7.1 参数传递的基本形式（10.7.1，P70～72）

| 方式 | 调用段传什么 | 被调用过程怎么用 | 特点 |
| --- | --- | --- | --- |
| 传值（call by value） | **实参的值**压入操作数栈 | 将值复制到形参单元，访问形参副本 | 修改形参不直接改变原实参，数据传递是单向的 |
| 传地址/引用（call by reference） | **实参地址**压栈 | 形参保存地址，通过地址间接访问实参 | 对形参所指内容的修改可直接反映到实参 |
| 传名（call by name） | 使每次引用形参相当于引用当时的实参表达式 | 引用时按实参表达式重新确定对象 | 当实参是数组元素时，可能与传地址不同，实现复杂、效率较低 |

P72 例题：初始 `I=1，A[1]=1，A[2]=2`，调用 `P(A[I])`；过程体先 `I:=I+1`，后 `x:=x+5`。

| 调用方式 | I 的最终值 | A[1] | A[2] | 原因 |
| --- | ---: | ---: | ---: | --- |
| 传值 | 2 | 1 | 2 | 只修改形参的独立副本 |
| 传地址 | 2 | 6 | 2 | 调用时固定指向 `A[1]` |
| 传名 | 2 | 1 | 7 | 使用 `x` 时 `I` 已变成 2，引用 `A[2]` |

## 7.2 过程调用的处理（10.7.2，P73～77）

一次过程调用要做：

1. 查符号表：过程是否已定义；过程/函数种类是否正确；实参与形参的类型、顺序、个数是否一致。
2. 计算并加载实参（值或地址）。
3. 保存返回地址 RA。
4. 转入过程入口地址。

例：`process_symb(symb,cursor,replacestr);`，课件 P74 对传值调用生成：

```text
LOD (addr of symb)
LOD (addr of cursor)
LOD (addr of replacestr)
JSR (addr of process_symb)
<retaddr>:
    ...
```

**本章的 JSR** 先把返回地址 `RA` 压入操作数栈，再跳到被调用过程入口。此时从栈顶向下依次是：`RA、replacestr、cursor、symb`。

P75：被调用过程入口处在**运行栈**上建立 AR，再把操作数栈的内容依次存入当前 AR：

```text
ALC, 4+x
STO, <actrec loc1>   保存 RA
STO, <actrec loc4>   保存 replacestr
STO, <actrec loc3>   保存 cursor
STO, <actrec loc2>   保存 symb
```

形参及 RA 的存储顺序与操作数栈**后进先出**对应。课件强调此时操作数栈、运行栈是两个不同的栈。

### 7.2.1 过程调用 ATG（P76～77）

```text
<proc call> -> <call head>↑i,z @initm↑m <args>↓i,z @genjsr↓i
<call head>↑i,z -> <id>↑n @lookupproc↓n↑i,z
<args>↓i,z -> @chklength↓i,z | '(' <arg list>↓i,z ')'
<arg list>↓i,z -> <expr>↑t @chktype↓t,i,m,z↑z <exprs>↓i,z
<exprs>↓i,z -> @chklength↓i,z
              | ',' <expr>↑t @chktype↓t,i,m,z↑z <exprs>↓i,z
```

属性含义：

- `n`：过程名；`i`：该过程名在符号表中的入口位置。
- `m`：已处理的实参数目，初值为 0，处理一个实参后 `m:=m+1`。
- `z`：尚未匹配的形参数目，初始化为过程形参数量；匹配一个实参后 `z:=z-1`。
- `t`：当前实参表达式的类型。

动作：

- `@lookupproc↓n↑i,z`：`i:=lookup(n)`；未找到则报错；找到后返回 `i` 及 `z:=symtbl[i].dim`（这里 `.dim` 保存**形参数目**）。
- `@initm`：初始化实参计数器 `m=0`。
- `@chktype↓t,i,m,z↑z`：若剩余形参数不足则报错；使 `m:=m+1`，比较 `t` 与 `symtbl[i+m].type`；使 `z:=z-1` 并返回。这里假设形参表项依次排列在过程名的表项后面。
- `@chklength`：最后检查 `z=0`；若仍大于 0 表明实参数目不足。
- `@genjsr↓i`：生成 `JSR symbtbl[i].addr`。

## 7.3 过程定义的 ATG（P78～80）

过程**调用**侧负责检查并加载实参、生成 `JSR`；过程**定义**侧负责登记过程名/形参、建立活动记录并接收参数。

```text
<proc defn> -> <proc defn head> @initcnt↑j
               <parameters>↓j↑k @emitstores↓k

<proc defn head> -> procedure↑t <id>↑n @tblinsert↓t,n

<parameters>↓j↑k -> @echo↓j↑k
                  | '(' <parm list>↓j↑k ')'

<parm list>↓j↑l -> <type>↑t ':' <id>↑n @tblinsert↓t,n
                   @upcnt↓j↑k <parms>↓k↑l

<parms>↓j↑l -> @echo↓j↑l
              | ',' <type>↑t ':' <id>↑n @tblinsert↓t,n
                @upcnt↓j↑k <parms>↓k↑l
```

主要动作：

- `@initcnt`：形参计数器置 `j=0`。
- `@tblinsert↓t,n`：先查重，再借助散列表和符号表，将过程名或形参名及其类型依次登记。
- `@upcnt↓j↑k`：`k:=j+1`，形参数量加一。
- `@echo↓j↑k`：`k:=j`，无更多形参时返回最终计数。
- `@emitstores↓k`：根据形参数量及固定空间，生成 `ALC` 分配 AR 的指令；再生成若干 `STO`，将返回地址与实参值从操作数栈保存到当前 AR 的相应单元。

例如过程名表项在 `i`，其三个形参依次在 `i+1、i+2、i+3`，就能在调用时按 `symtbl[i+m].type` 检查第 `m` 个形参类型。

**反填 ALC**（P80）：过程入口处生成 `ALC` 时，可能还未完成全部局部变量声明，因此活动记录所需空间未完全确定；待所有局部变量处理完成、计算出包含固定空间在内的总大小后，再把大小**反填回 ALC 指令的操作数**。

## 7.4 返回语句和过程体结束（10.7.3，P81）

1. **函数结果**：若为函数过程，将操作数栈（或运行栈）顶的结果值存入函数结果单元。
2. **返回控制流**：生成转移到返回地址的指令，课件写成 `JMP RA`。`RA` 决定返回后继续执行的位置。
3. **恢复运行环境**：回收被调用过程的活动记录，可根据**动态链 DL** 恢复调用者的活动记录基址 `abp`。

容易混淆的点：

- `RA`（Return Address）解决“**返回到哪里执行**”。
- `DL`（Dynamic Link）解决“**返回到哪个调用者活动记录**”。
- 函数**返回值**与**返回地址**不是一回事。
- PPT 列举的是返回处理任务，实际执行顺序须保证恢复运行环境后仍能正确返回调用者。
