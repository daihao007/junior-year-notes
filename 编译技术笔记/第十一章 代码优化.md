# 第十一章 代码优化

## 概述


### 定义与目标

代码优化：编译程序为了生成高质量目标程序而进行的各种加工和处理。

- 时间效率：减少程序运行时间。
- 空间效率：减少程序占用的存储容量。
- 基本原则：不能改变原有程序的语义。

### 优化的意义

- 简单的局部优化通常可以以较低代价取得明显效果。
- 进一步优化可能需要更多编译时间和分析成本。
- 循环通常占用大量执行时间，因此循环优化十分重要。
- 优化效果取决于具体程序，并非所有优化都值得实施。

### 优化的分类

#### 按是否与机器有关

1. 与机器无关的优化：通常在中间代码上进行，例如常量传播、公共子表达式删除、死代码删除。
2. 与机器有关的优化：充分利用目标机器指令系统、寄存器资源等，例如寄存器分配、指令调度。

#### 按优化范围

1. 局部优化：在单个基本块内进行。
2. 循环优化：针对循环结构进行优化。
3. 全局优化：跨越多个基本块，需要控制流和数据流分析。
4. 跨函数优化：在整个程序范围内进行分析和优化。

### 典型例题

固定循环求和：

```c
int count = 0;
for (int i = 1; i <= 100; i++)
    count += i;
```

在不存在其他副作用的情况下，可将结果直接确定为 `count = 5050`，消除循环。

### 重点与易错点

- 优化的首要前提是保持原程序语义不变。
- 代码长度变短不一定意味着运行速度更快。
- 机器相关性和优化范围是两种独立的分类标准。
- 全局优化涉及多个基本块，通常需要控制流和数据流分析。

## 14.1 基本块和流图

### 基本块（Basic Block）

#### 定义

基本块是具有单一入口、单一出口的最大连续语句序列。

基本块的特点：

1. 基本块中的代码是连续的语句序列。
2. 控制流只能从基本块的第一条语句进入。
3. 控制流只能从基本块的最后一条语句离开。

性质：在正常执行情况下，进入基本块后将顺序执行其中的全部语句。

#### 划分基本块的算法（算法14.1）

输入：四元式序列。
输出：基本块列表，每条四元式仅属于一个基本块。

**步骤一：确定入口语句（Leader）**

- 规则1：整个语句序列的第一条语句。
- 规则2：条件或无条件跳转语句的目标语句。
- 规则3：紧跟在跳转语句之后的第一条语句。

**步骤二：划分基本块**

从每个入口语句开始，直到下一个入口语句之前，所有连续语句属于同一个基本块。

记忆方法：先找入口，再按入口切分。

### 基本块划分例题

三地址中间代码：

```text
(1)  prod := 0
(2)  i := 1
(3)  t1 := 4 * i
(4)  t2 := a[t1]
(5)  t3 := 4 * i
(6)  t4 := b[t3]
(7)  t5 := t2 * t4
(8)  t6 := prod + t5
(9)  prod := t6
(10) t7 := i + 1
(11) i := t7
(12) if i <= 20 goto (3)
(13) ...
```

**找入口：**

- 规则1：语句(1)。
- 规则2：语句(12)跳转到(3)，故(3)是入口。
- 规则3：跳转语句(12)之后为(13)，故(13)是入口。

因此：

$$
Leader=\{1,3,13\}
$$

**划分结果：**

- B0：语句(1)～(2)
- B1：语句(3)～(12)
- B2：语句(13)

### 流图（Flow Graph / CFG）

#### 定义

流图是一种有向图：

- 结点：基本块。
- 有向边：基本块之间可能发生的控制转移。

若存在边 B1 → B2，则：

- B1 是 B2 的前驱（Predecessor）。
- B2 是 B1 的后继（Successor）。

#### 构造有向边的规则

以下任一情况成立，则建立 B1 → B2：

1. B1的最后一条语句可以通过条件或无条件跳转到B2的第一条语句。
2. B2在代码顺序上紧跟B1，且B1没有无条件跳转到其他基本块。

#### 课件例题的流图

- B0 → B1：初始化后顺序进入循环。
- B1 → B1：若 i <= 20，跳回循环体。
- B1 → B2：若 i > 20，退出循环。

边集合：

$$
E=\{(B_0,B_1),(B_1,B_1),(B_1,B_2)\}
$$

### 重点与易错点

1. 基本块具有单一入口和单一出口。
2. 跳转目标语句和跳转后继语句都是入口语句。
3. 跳转语句本身通常是所在基本块的最后一条语句。
4. 基本块允许自环，这是循环控制流的常见结构。
5. 有向边表示可能的执行关系，而不是单纯的代码排列关系。
6. 无条件跳转之后紧跟的语句依然是划分算法规定的入口，即使它可能不可达。
7. 基本块是局部优化的基本单位，流图则是全局控制流和数据流分析的基础。

### 解题步骤总结

1. 编号并检查全部中间代码。
2. 按三条规则标出全部入口语句。
3. 根据入口语句切分基本块。
4. 将每个基本块画成一个结点。
5. 检查每个基本块最后一条语句的转移关系。
6. 画出跳转边、顺序执行边，形成流图。

## 14.2 基本块内优化

### 利用代数性质（代数变换）

#### 常数合并（Constant Folding）

在编译时完成常量表达式的计算，减少运行时的运算开销。

例如：

```text
a := 5 + 6 + x
```

优化后：

```text
a := 11 + x
```

编译器也可提前完成常量表达式的类型转换，如实型变量 x：

```text
x := 3 + 1
```

可变换为：

```text
x := 4.0
```

数组地址计算也可以提前完成常量部分，只在运行时计算与下标相关的可变部分。

#### 运算强度削弱（Strength Reduction）

定义：用一种执行代价较低的运算代替另一种代价较高的运算，在保持语义不变的前提下减少运行时开销。

课件例子：

- x ** 2 → x * x
- 3 * x → x + x + x
- 8 * x → x << 3
- 4 * x → x << 2
- x / 2 → x >> 1
- x / 16 → x >> 4
- x := x + 1 → INC x
- x / 5 → x * 0.2

注意：以上转换需要满足对应的类型、溢出、舍入和目标机器语义要求，并非全部无条件等价。

区别：

- 常数合并：能在编译阶段确定的计算，提前完成。
- 运算强度削弱：运行时仍需计算，但选择更高效的运算方式。

### 复写传播（Copy Propagation）

#### 定义

形如 x := y 的赋值语句称为复写语句。

由于赋值后 x 和 y 的值相同，因此满足条件时，可将后面引用 x 的地方替换为 y。

例如：

```text
x := y
u := 2 * x
v := x + 1
```

传播后：

```text
x := y
u := 2 * y
v := y + 1
```

#### 复写传播的条件

从复写语句到使用点之间：

1. 源变量 y 的值没有被修改。
2. 目标变量 x 没有被其他赋值覆盖。
3. 没有其他操作破坏 x 和 y 值相同的关系。

例如：

```text
x := y
y := 10
u := x + 1
```

不能将 u := x + 1 改为 u := y + 1，因为 y 已被重新赋值。

如果传播完成后，x 的这次赋值在后续也不再需要，则可进一步删除 x := y。

### 常量传播（Constant Propagation）

当赋值语句为 x := 常量时，满足条件可将后续对 x 的引用替换为该常量。

例如：

```text
x := 3
u := 2 * x
v := x + 1
```

常量传播：

```text
x := 3
u := 2 * 3
v := 3 + 1
```

常数合并：

```text
x := 3
u := 6
v := 4
```

若后续不再需要 x，则可删除 x := 3。

临时变量消除：

```text
t1 := y / z
x := t1
```

若 t1 后续不再使用，可以化简为：

```text
x := y / z
```

### 删除冗余代码（Dead Code Elimination）

#### 定义

删除对需要保留的程序结果没有影响的冗余代码、死代码或无用代码。

#### 典型情况

**情况一：无效运算**

```text
x := x + 0
x := x * 1
```

在通常整数运算语义下可删除。

**情况二：不可达代码**

```text
FLAG := TRUE
IF FLAG THEN ...
ELSE ...
```

如果 FLAG 恒为真，则 ELSE 分支不会执行，可以删除。

**情况三：调试代码**

```text
if debug then ...
```

如果 debug 为 false，相关代码可以删除。

也可以采用条件编译：

```c
#if DEBUG
    printf("debug information\n");
#endif
```

**情况四：无用赋值**

```text
x := 5
x := 8
y := x + 1
```

第一次赋值的结果从未被使用就被覆盖，因此 x := 5 可以删除。

### 各优化方法的联系

| 方法         | 核心思想                           |
| ------------ | ---------------------------------- |
| 常数合并     | 提前计算已知的常量表达式           |
| 运算强度削弱 | 使用代价更低的等价运算             |
| 复写传播     | 用源变量替换目标变量的后续引用     |
| 常量传播     | 用已知常量替换变量引用             |
| 冗余代码删除 | 删除无用计算、无用赋值和不可达代码 |

多种优化可以连续使用。

例如：

```text
x := 3
u := 2 * x
v := x + 1
```

先进行常量传播，再进行常数合并。若 x 不再使用，还可删除 x := 3。

### 重点与易错点

1. 代码优化必须保持程序语义不变。
2. 常数合并和常量传播不是同一概念：前者计算常量表达式，后者传播已知常量值。
3. 复写传播必须确保在传播区间内变量值的相等关系仍成立。
4. 复写传播之后，不一定能删除原来的赋值语句，需要分析后续是否仍使用其结果。
5. 运算强度削弱不是简单地将乘法换成加法，必须考虑目标机器的实际执行代价。
6. 有符号整数除法不能无条件转换为右移。
7. 删除无用赋值需要考虑跨基本块的变量使用情况。
8. 不同优化技术可以组合使用，一种优化可能触发另一种优化。


### 公共子表达式删除

若多个表达式具有相同的操作符及操作数值，且相关值没有被重新定义，则可以复用已有计算结果，避免重复计算。

例如：

```text
t1 := -c
t2 := b * t1
t3 := -c
t4 := b * t3
t5 := t2 + t4
a  := t5
```

优化后：

```text
t1 := -c
t2 := b * t1
t5 := t2 + t2
a  := t5
```

注意：表达式形式相同不一定代表计算结果相同，需要考虑操作数是否被修改。

### DAG 图的定义

DAG（Directed Acyclic Graph）即有向无环图。

用于表示基本块中各中间代码的计算依赖关系，并通过共享结点消除公共子表达式。

#### DAG 与语法树的区别

- 语法树：重复计算可以对应不同子树。
- DAG：相同计算结果可共用一个结点。
- DAG 允许一个结点被多个父结点引用。

### DAG 图的结点

1. 叶结点：由变量或常量标记。
2. 中间结点：由运算符标记。
3. 一个中间结点可代表一条或多条中间代码。
4. 基本块中变量的最终值对应某个 DAG 结点。
5. 同一变量的初值和最终值可能对应不同结点。

其中：

$$
x_0=\text{变量 x 进入基本块时的值}
$$

注意：x₀ 不代表 x=0。

### 结点表 node(x)

结点表记录变量名或常量值与当前 DAG 结点编号的对应关系。

例如：

| 变量 | node(x) |
| ---- | ------- |
| a    | 1       |
| t1   | 3       |
| t2   | 3       |

表示 t1 与 t2 对应同一个结点 3。

一个结点可以对应多个变量；一个变量重新赋值后，其结点表项也需要更新。

### 算法 14.2：构建 DAG

输入：基本块内的中间代码序列。

输出：经过局部公共子表达式合并的 DAG 图。

步骤：

1. 创建空 DAG 图和空结点表。
2. 从第一条中间代码开始，依次处理。
3. 对于 `z := x op y`：
   - 查询 x 当前的结点号 i。
   - 查询 y 当前的结点号 j。
   - 如果操作数不存在，则创建叶结点并更新结点表。
4. 在 DAG 中查找运算符为 op，左儿子为 i、右儿子为 j 的结点。
   - 若存在，复用该结点 k。
   - 若不存在，创建新结点 k。
5. 更新目标变量 z 对应的结点号：node(z)=k。
6. 重复直到全部中间代码处理完成。

特殊形式：

- `z := -x`：查找一个操作数结点。
- `z := x`：不需要创建运算结点，直接令 node(z)=node(x)。

### 例题一：相同计算结点的复用

```text
(1) t1 := -c
(2) t2 := b * t1
(3) t3 := -c
(4) t4 := b * t3
(5) t5 := t2 + t4
(6) a  := t5
```

DAG 结点：

- N1 = c₀
- N2 = -(N1)
- N3 = b₀
- N4 = ×(N3, N2)
- N5 = +(N4, N4)

最终结点表：

| 变量 | 结点号 |
| ---- | ------ |
| c    | 1      |
| t1   | 2      |
| b    | 3      |
| t2   | 4      |
| t3   | 2      |
| t4   | 4      |
| t5   | 5      |
| a    | 5      |

公共子表达式：

$$
node(t_1)=node(t_3)=2
$$

$$
node(t_2)=node(t_4)=4
$$

所以取负和乘法运算均可以复用。

### 例题二：变量重新赋值

```text
(1) t1 := -c
(2) t2 := b * t1
(3) c  := t1
(4) t3 := -c
(5) t4 := b * t3
(6) t5 := c + t4
(7) a  := t5
```

DAG 结点：

- N1 = c₀
- N2 = -(N1)
- N3 = b₀
- N4 = ×(N3, N2)
- 执行 c := t1，更新 node(c) 为 2
- N5 = -(N2)
- N6 = ×(N3, N5)
- N7 = +(N2, N6)

最终结点表：

| 变量 | 结点号 |
| ---- | ------ |
| c    | 2      |
| t1   | 2      |
| b    | 3      |
| t2   | 4      |
| t3   | 5      |
| t4   | 6      |
| t5   | 7      |
| a    | 7      |

注意：

- 第一次 `-c` 的操作数结点是 1。
- 执行 `c := t1` 后，c 的结点号由 1 更新为 2。
- 第二次 `-c` 的操作数结点是 2。
- 因此两次取负不能按照相同运算结点直接合并。

### 易错点

1. DAG 是有向无环图，允许多个父结点引用同一结点。
2. node(x) 表示 x 当前对应的值结点，不是变量的固定编号。
3. x₀ 表示变量进入基本块时的初值。
4. 一个 DAG 结点可以对应多个变量名。
5. 变量重新赋值后需要更新结点表，不能直接修改旧结点所代表的计算结果。
6. 简单赋值 z:=x 不创建新运算结点。
7. 两个表达式书写相同不一定能复用，必须比较其操作数当前对应的结点。
8. 构建 DAG 与从 DAG 重新导出中间代码是两个不同的算法。


### 数组、指针和函数调用的 DAG 表示

#### 数组访问

对于：

```text
x := a[i]
a[j] := y
z := a[i]
```

不能直接认为 x=z，因为当 i=j 时，第二条语句修改了 a[i] 的值。

处理方式：

- 将数组 a 作为一个整体变量考虑。
- 使用 `[]` 表示数组取值。
- 使用 `[]=` 表示数组成员赋值。
- 数组写入后，需要正确反映数组状态的变化。

核心：两次数组读取即使下标相同，其依赖的数组状态也可能不同。

#### 指针访问

例如：

```c
x = *p;
*q = y;
z = *p;
```

如果 p 和 q 指向同一内存位置，则 *q=y 会改变 *p 的值。

因此：

- 指针之间可能存在别名（Alias）。
- 无法判断是否存在别名时，需要保守处理。
- 不能轻易合并可能受到指针写入影响的读取操作。

#### 函数调用

函数调用可能改变全局变量或其他可访问的数据。

在缺乏跨函数数据流分析时，应保守地假设函数调用改变了它可能改变的数据。

### 从 DAG 重新导出中间代码

#### 基本原则

- 一个运算结点必须在其操作数计算完成后执行。
- 同一个 DAG 可能对应多种正确的中间代码顺序。
- 不同顺序可能产生不同的寄存器需求和内存访问次数。

#### 课件例题

原始代码：

```text
t1 := a + b
t2 := c + d
t3 := e - t2
t4 := t1 - t3
```

DAG 计算关系：

- t1 = a+b
- t2 = c+d
- t3 = e-t2
- t4 = t1-t3

依赖关系：

- t2 必须先于 t3。
- t1 和 t3 必须先于 t4。
- t1 和 t2 没有直接依赖关系。

可以采用两种顺序。

**顺序一**

```text
t1 := a + b
t2 := c + d
t3 := e - t2
t4 := t1 - t3
```

**顺序二**

```text
t2 := c + d
t3 := e - t2
t1 := a + b
t4 := t1 - t3
```

#### 寄存器与内存交互

课件假设：

- 局部变量 a、b、c、d、e 均不预先占用寄存器。
- 仅有 eax、edx 两个寄存器可供使用。

顺序一：

- 先计算 t1 和 t2，两个寄存器均被占用。
- 计算 t3 时需要腾出寄存器，因此保存 t1。
- 计算 t4 时需要重新读取 t1。
- 按课件展示的汇编，发生 3 次临时寄存器与内存交互。

顺序二：

- 先计算 t2，随后立即计算 t3。
- 再计算 t1，随后立即计算 t4。
- 按课件展示的汇编，发生 2 次临时寄存器与内存交互。

注意：课件展示的两段汇编均还有可以删除的冗余保存指令。3 次和 2 次是对课件给定序列的统计，并非最低可能次数。

核心结论：合理安排计算顺序，可以减少寄存器不足引起的临时结果保存与恢复。

### 算法 14.3：从 DAG 导出中间代码的启发式算法

**输入：** DAG 图。

**输出：** 中间代码序列。

#### 算法步骤

1. 初始化一个存放 DAG 中间结点的空队列。

2. 如果还有中间结点未进入队列，则继续；否则执行步骤 5。

3. 选择一个尚未入队，并且所有父结点均已入队的中间结点，将其加入队列。没有父结点的中间结点也可以入队。

4. 沿当前结点的最左子结点向下访问。若子结点是符合条件的中间结点，则继续入队；若不满足条件，则返回步骤 2。

5. 将中间结点队列逆序输出，得到计算顺序，整理为中间代码序列。

#### 课件例题

DAG 包含四个运算结点：

- t4：根结点
- t1：t4 左子结点
- t3：t4 右子结点
- t2：t3 的右子结点

按照算法，入队顺序为：

$$
[t_4,t_1,t_3,t_2]
$$

逆序输出：

$$
[t_2,t_3,t_1,t_4]
$$

得到：

```text
t2 := c + d
t3 := e - t2
t1 := a + b
t4 := t1 - t3
```

**为什么逆序？**

因为构造队列时先访问父结点，再访问子结点，而实际计算必须先执行被依赖的子结点，再执行父结点。

**算法性质：**

算法 14.3 是启发式算法，并不保证所有情况下都能得到全局最优指令序列。

### 窥孔优化

#### 定义

窥孔优化（Peephole Optimization）针对较短的目标指令序列进行检查，通过删除冗余指令或采用更高效的指令来提升目标代码质量。

#### 删除冗余数据传送

```asm
mov EAX, [ESP+08H]
mov [ESP+08H], EAX
```

在满足语义等价条件时，可以删除第二条写回指令。

课件指出，这类直接删除要求相关指令位于同一基本块中。

#### 删除多余跳转

```asm
jmp B2
B2:
    ...
```

如果 B2 恰好是顺序执行的下一条代码，则可以删除这条跳转。

#### 特点

- 通常直接处理目标指令。
- 检查较短的指令序列。
- 可以删除冗余指令或进行指令替换。
- 不一定局限于同一个基本块。
- 必须保持程序原有语义。

### 本节重点

1. 数组、指针和函数调用可能间接改变数据，DAG 优化必须考虑别名及副作用。
2. 构造 DAG 与从 DAG 导出中间代码是两个不同的步骤。
3. 一张 DAG 可以对应多个符合依赖关系的计算顺序。
4. 计算顺序会影响临时值的存活时间和寄存器需求。
5. 算法 14.3 先按规则将中间结点入队，再逆序输出。
6. 窥孔优化主要针对较短的目标指令序列。
7. 代码优化始终必须保证程序语义不变。

## 14.3 全局优化

### 14.3.1 数据流分析

#### 数据流分析概述

数据流分析（Data Flow Analysis）：用于获取数据在程序执行路径中如何流动的有关信息，是全局优化的基础。

主要分析：

- 某个变量在某个程序点是否活跃。
- 某个变量的值来自哪个定义点。
- 某个定义点产生的值可能在哪些位置被使用。

程序的执行过程就是程序状态不断变化的过程。

控制流分析关注程序可能如何执行；数据流分析关注变量的值如何在这些执行路径中传播。

#### 数据流分析方程

基本方程：

$$
out[S]=gen[S]\cup(in[S]-kill[S])
$$

其中：

- `in[S]`：进入 S 时的数据流信息。
- `out[S]`：离开 S 时的数据流信息。
- `gen[S]`：S 本身产生的数据流信息。
- `kill[S]`：S 注销的数据流信息。

直观理解：

OUT = 新产生的信息 ∪ 未被注销的旧信息

数据流分析需要考虑：

1. 分析问题的不同会导致 gen、kill 的具体定义不同。
2. 数据流分析受到控制流结构的影响。
3. 函数调用、指针和数组访问会增加分析难度。

#### 到达定义（Reaching Definition）

##### 定义点

程序中对变量进行定义的语句，例如赋值语句，称为定义点。

同一个变量可能存在多个定义点。

例如：

```text
d1: x = 10
d2: y = 20
d3: x = 30
```

d1 和 d3 都是变量 x 的定义点。

##### 到达定义

如果从定义点 d 出发，存在一条路径到达程序点 p，并且这条路径上不存在对同一变量的其他定义，那么称定义点 d 到达程序点 p。

注意：

- 只要求存在一条路径。
- 路径上不能存在同一变量的重新定义。
- 到达定义分析是一种可能性分析。

##### 定义点被杀死

如果后续语句重新定义了同一个变量，那么之前的定义就被杀死（kill）。

例如：

```text
d1: x = 10
d2: x = 20
```

执行完 d2 后，d1 对 x 的定义不再有效。

#### 单条语句的 gen 和 kill

对于语句：
$d_1: u = v\;\mathrm{op}\;w$

有：
$gen[d_1]=\{d_1\}$
$kill[d_1]=\text{程序中所有其他定义变量 u 的定义点}$

单条语句的数据流方程：
$out[d_1]=gen[d_1]\cup(in[d_1]-kill[d_1])$

注意：

kill 集合需要考虑整个程序中的其他定义点，包括代码位置在该语句之后的定义点，因为程序可能存在循环回边。

同一个基本块中的连续语句满足：

$$
in[d_{i+1}]=out[d_i]
$$

#### 基本块的 gen 和 kill

基本块数据流方程：

$$
out[B]=gen[B]\cup(in[B]-kill[B])
$$

其中：

$$
kill[B]=\bigcup_{i=1}^{n}kill[d_i]
$$

基本块的 gen[B] 是基本块内部产生且没有被后续语句杀死的定义点集合。

对于依次执行的 d1～dn：

$$
\begin{aligned}
gen[B]={}&gen[d_n]\\
&\cup(gen[d_{n-1}]-kill[d_n])\\
&\cup\cdots\\
&\cup(gen[d_1]-kill[d_2]-\cdots-kill[d_n])
\end{aligned}
$$

例：

```text
d1: a = b + 1
d2: a = b + 2
```

假设程序中 a 仅有这两个定义点：

$$
kill[B]=\{d_1,d_2\}
$$

$$
gen[B]=\{d_2\}
$$

因为 d1 对 a 的定义在基本块出口之前已被 d2 覆盖。

#### 基本块之间的数据流关系

对某个基本块 B：

$$
in[B]=\bigcup_{P\in pred(B)}out[P]
$$

其中 pred(B) 表示 B 的全部前驱基本块。

因此到达定义分析的两个核心方程为：

$$
\boxed{in[B]=\bigcup_{P\in pred(B)}out[P]}
$$

$$
\boxed{out[B]=gen[B]\cup(in[B]-kill[B])}
$$

到达定义是一种沿控制流方向进行的前向数据流分析。

#### 算法 14.4：到达定义的迭代求解

输入：程序流图，各基本块的 gen 和 kill 集合。

输出：每个基本块入口、出口处的 in 和 out 集合。

步骤：

1. 将所有基本块的 out 集合初始化为空集。
2. 对每个基本块 B 计算：

$$
in[B]=\bigcup_{P\in pred(B)}out[P]
$$

$$
out[B]=gen[B]\cup(in[B]-kill[B])
$$

3. 如果某个基本块的 out 集合发生变化，则重新迭代。
4. 直到所有 out 集合均不再变化，算法结束。

最终稳定的结果称为不动点（Fixed Point）。

#### 课件完整例题

##### 基本块

B1：

```text
d1: x = a
d2: y = b
d3: i = 0
```

B2：

```text
cmp i, 100
```

B3：

```text
d4: z = a * 10
d5: x = x + y
cmp x, z
```

B4：

```text
d6: x = x - y
```

B5：

```text
d7: y = y + 1
d8: i = i + 1
```

Bexit：出口。

##### 控制流关系

- B1 → B2
- B2 → B3
- B2 → Bexit
- B3 → B4
- B3 → B5
- B4 → B5
- B5 → B2

因此：

$$
in[B_1]=\varnothing
$$

$$
in[B_2]=out[B_1]\cup out[B_5]
$$

$$
in[B_3]=out[B_2]
$$

$$
in[B_4]=out[B_3]
$$

$$
in[B_5]=out[B_3]\cup out[B_4]
$$

$$
in[B_{exit}]=out[B_2]
$$

##### gen / kill 集合

| 基本块 | gen        | kill          |
| ------ | ---------- | ------------- |
| B1     | {d1,d2,d3} | {d5,d6,d7,d8} |
| B2     | ∅          | ∅             |
| B3     | {d4,d5}    | {d1,d6}       |
| B4     | {d6}       | {d1,d5}       |
| B5     | {d7,d8}    | {d2,d3}       |
| Bexit  | ∅          | ∅             |

##### 第一轮迭代

初始化所有 out 为空集。

按照 B1、B2、B3、B4、B5、Bexit 的顺序计算：

| 基本块 | in               | out              |
| ------ | ---------------- | ---------------- |
| B1     | ∅                | {d1,d2,d3}       |
| B2     | {d1,d2,d3}       | {d1,d2,d3}       |
| B3     | {d1,d2,d3}       | {d2,d3,d4,d5}    |
| B4     | {d2,d3,d4,d5}    | {d2,d3,d4,d6}    |
| B5     | {d2,d3,d4,d5,d6} | {d4,d5,d6,d7,d8} |
| Bexit  | {d1,d2,d3}       | {d1,d2,d3}       |

第一轮结束时，B5 的 out 已更新，因此它会影响下一轮 B2 的 in。

##### 第二轮迭代

B2 的入口集合发生变化：

$$
\begin{aligned}
in[B_2]
&=out[B_1]\cup out[B_5]\\
&=\{d_1,d_2,d_3\}\cup\{d_4,d_5,d_6,d_7,d_8\}\\
&=\{d_1,d_2,d_3,d_4,d_5,d_6,d_7,d_8\}
\end{aligned}
$$

第二轮结果：

| 基本块 | in                        | out                       |
| ------ | ------------------------- | ------------------------- |
| B1     | ∅                         | {d1,d2,d3}                |
| B2     | {d1,d2,d3,d4,d5,d6,d7,d8} | {d1,d2,d3,d4,d5,d6,d7,d8} |
| B3     | {d1,d2,d3,d4,d5,d6,d7,d8} | {d2,d3,d4,d5,d7,d8}       |
| B4     | {d2,d3,d4,d5,d7,d8}       | {d2,d3,d4,d6,d7,d8}       |
| B5     | {d2,d3,d4,d5,d6,d7,d8}    | {d4,d5,d6,d7,d8}          |
| Bexit  | {d1,d2,d3,d4,d5,d6,d7,d8} | {d1,d2,d3,d4,d5,d6,d7,d8} |

第三轮所有 out 集合不再变化，因此算法收敛。

第二轮的结果即为最终结果。

#### 位向量（Bit Vector）

使用二进制位表示集合中的定义点是否存在。

例如，八个定义点 d1～d8，对应二进制位从低位到高位依次排列。

$$
out[B_3]=\{d_2,d_3,d_4,d_5,d_7,d_8\}
$$

对应：

$$
out[B_3]=11011110_2
$$

集合运算可以通过位运算实现：

- 并集：按位或 OR
- 差集：按位与 AND、按位取反 NOT

因此：

$$
OUT=GEN\ |\ (IN\ \&\ \sim KILL)
$$

注意：

- d1 对应最低位，即最右边一位。
- 按位取反需要限制有效位数。

#### 重点与易错点

1. 到达定义分析是前向数据流分析。
2. 定义点代表赋值语句，而不是变量本身。
3. 同一变量可能有多个定义点。
4. 定义 d 到达程序点 p，只需要存在一条没有被重新定义阻断的路径。
5. kill[d] 包含程序中所有对同一变量的其他定义点。
6. gen[B] 只包含块内产生且能够保留到出口的定义。
7. in[B] 等于所有前驱基本块 out 集合的并集。
8. out[B] 等于新产生的定义与未被注销的旧定义的并集。
9. 由于循环回边的存在，通常需要迭代求解。
10. 每轮迭代时使用的基本块更新顺序可能影响中间结果，但最终应收敛到相同的不动点。
11. 位向量可以提高集合运算效率。
12. 本章后续的活跃变量分析与到达定义不同，它是反向数据流分析。

### 14.3.2 活跃变量分析（Live-variable Analysis）

#### 活跃变量的定义

对于程序点 p，如果变量 x 当前保存的值在 p 点或从 p 出发的某条执行路径上可能被使用，且在使用之前没有被重新定义，则称 x 在 p 点是活跃的（Live）。

否则称为非活跃的（Dead）。

##### 关键理解

1. 判断的是变量当前保存的值是否还会被使用。
2. 只要存在一条可能使用该值的路径，变量就是活跃的。
3. 如果变量的旧值在再次使用前被覆盖，则旧值不再活跃。
4. 活跃性与具体的程序位置有关。

例如：

```text
(1) x := 10
(2) y := x + 1
(3) x := 20
(4) z := x * 2
```

- (1) 后：x 活跃，因为 (2) 会使用它。
- (2) 后：x 不活跃，因为旧值不会再使用。
- (3) 后：x 活跃，因为 (4) 会使用新值。
- (4) 后：若之后不再使用 x，则 x 不活跃。

#### 活跃变量分析的意义

主要用于寄存器分配：

1. 如果变量在某个程序点之后不再活跃，可以释放它占用的寄存器。
2. 如果两个变量的活跃范围不重合，可以共享同一个寄存器。
3. 减少不必要的寄存器占用和内存访问。

#### 活跃变量数据流方程

两个核心方程：

$$
\boxed{out[B]=\bigcup_{S\in succ(B)}in[S]}
$$

$$
\boxed{in[B]=use[B]\cup(out[B]-def[B])}
$$

其中：

- `succ(B)`：B 的所有后继基本块。
- `in[B]`：进入 B 时活跃的变量集合。
- `out[B]`：离开 B 时活跃的变量集合。
- `use[B]`：在 B 中定义之前被使用的变量集合。
- `def[B]`：按本课件的约定，在 B 中先于任何使用而被定义的变量集合。

##### 公式理解

`out[B]`：

如果变量在任意一个后继基本块入口处活跃，那么它在 B 的出口处也活跃。

`in[B]`：

进入 B 时需要保留两类变量：

1. B 内部使用前尚未定义的变量。
2. B 后续还需要使用、但没有被 B 提前定义的变量。

因此：

$$
IN=USE\cup(OUT-DEF)
$$

#### 与到达定义分析的区别

| 比较项   | 到达定义分析 | 活跃变量分析 |
| -------- | ------------ | ------------ |
| 分析方向 | 前向         | 反向         |
| 分析对象 | 定义点       | 变量         |
| 产生集合 | gen          | use          |
| 注销集合 | kill         | def          |
| 信息汇集 | 前驱 out     | 后继 in      |
| 迭代重点 | out          | in           |

到达定义：

$$
in[B]=\bigcup_{P\in pred(B)}out[P]
$$

$$
out[B]=gen[B]\cup(in[B]-kill[B])
$$

活跃变量：

$$
out[B]=\bigcup_{S\in succ(B)}in[S]
$$

$$
in[B]=use[B]\cup(out[B]-def[B])
$$

#### use 和 def 的计算

##### use[B]

在基本块中，变量在定义之前被使用，则属于 use[B]。

例如：

```text
x := a + b
y := x + c
```

结果：

$$
use[B]=\{a,b,c\}
$$

因为：

- a、b 首次使用之前没有定义。
- x 在第二条语句使用前已经定义。
- c 在使用前没有定义。

##### def[B]

按照本课件的定义，变量在使用之前被定义，则属于 def[B]。

上例：

$$
def[B]=\{x,y\}
$$

特别注意：

```text
x := x + 1
```

在读取右侧 x 之后，才重新定义左侧 x。

按照课件约定：

$$
use[B]=\{x\}
$$

$$
def[B]=\varnothing
$$

不同教材可能使用包含全部块内赋值变量的 def 定义；本章计算按 PPT 约定。

$$
out[B_1]=in[B_2]
$$

$$

#### 算法 14.5

输入：控制流图，各基本块的 use、def 集合。

输出：各基本块的 in、out 集合。

##### 步骤

1. 将所有基本块的 in 初始化为空集。
2. 根据后继基本块的 in 求出当前基本块的 out。
3. 利用 use、def、out 计算 in。
4. 如果 in 集合发生变化，继续迭代。
5. 直到全部 in 集合稳定，算法结束。

伪代码：

```text
for each block B:
    in[B] = ∅

repeat:
    for each block B:
        out[B] = union(in[S] for S in succ(B))
        in[B] = use[B] ∪ (out[B] - def[B])

until all in[B] remain unchanged
```

##### 第一轮迭代

初始状态：

$$
\forall B,\quad in[B]=\varnothing
$$

按照 Bexit、B5、B4、B3、B2、B1 顺序计算。

B5：

$$
out[B_5]=\varnothing
$$

$$
in[B_5]=\{y,i\}
$$

B4：

$$
out[B_4]=in[B_5]=\{y,i\}
$$

$$
in[B_4]=\{x,y\}\cup\{y,i\}=\{x,y,i\}
$$

B3：

$$
out[B_3]=in[B_4]\cup in[B_5]=\{x,y,i\}
$$

$$
in[B_3]=\{a,x,y\}\cup(\{x,y,i\}-\{z\})
$$

$$
in[B_3]=\{a,x,y,i\}
$$

B2：

$$
out[B_2]=in[B_3]\cup in[B_{exit}]
$$

$$
out[B_2]=\{a,x,y,i\}
$$

$$
in[B_2]=\{i\}\cup\{a,x,y,i\}
=\{a,x,y,i\}
$$

B1：

$$
out[B_1]=in[B_2]=\{a,x,y,i\}
$$

$$
in[B_1]=\{a,b\}\cup(\{a,x,y,i\}-\{x,y,i\})
$$

$$
in[B_1]=\{a,b\}
$$

第一轮汇总：

| 基本块 | in        | out       |
| ------ | --------- | --------- |
| B1     | {a,b}     | {a,x,y,i} |
| B2     | {a,x,y,i} | {a,x,y,i} |
| B3     | {a,x,y,i} | {x,y,i}   |
| B4     | {x,y,i}   | {y,i}     |
| B5     | {y,i}     | ∅         |
| Bexit  | ∅         | ∅         |

##### 第二轮迭代

B5：

$$
out[B_5]=in[B_2]=\{a,x,y,i\}
$$

$$
in[B_5]=\{y,i\}\cup\{a,x,y,i\}
=\{a,x,y,i\}
$$

B4：

$$
out[B_4]=in[B_5]=\{a,x,y,i\}
$$

$$
in[B_4]=\{x,y\}\cup\{a,x,y,i\}
=\{a,x,y,i\}
$$

B3：

$$
out[B_3]=in[B_4]\cup in[B_5]
=\{a,x,y,i\}
$$

$$
in[B_3]=\{a,x,y\}\cup(\{a,x,y,i\}-\{z\})
=\{a,x,y,i\}
$$

B2：

$$
out[B_2]=\{a,x,y,i\}
$$

$$
in[B_2]=\{a,x,y,i\}
$$

B1：

$$
out[B_1]=\{a,x,y,i\}
$$

$$
in[B_1]=\{a,b\}
$$

第二轮结果：

| 基本块 | in        | out       |
| ------ | --------- | --------- |
| B1     | {a,b}     | {a,x,y,i} |
| B2     | {a,x,y,i} | {a,x,y,i} |
| B3     | {a,x,y,i} | {a,x,y,i} |
| B4     | {a,x,y,i} | {a,x,y,i} |
| B5     | {a,x,y,i} | {a,x,y,i} |
| Bexit  | ∅         | ∅         |

第三轮集合不再变化，因此第二轮结果就是最终结果。

#### 最终结果分析

##### 变量 x、y、i

均在 B1 中定义，在后续基本块中被使用，因此在 B2～B5 入口处均活跃。

其中 x、y、i 在一些基本块中虽然被重新定义，但重新定义之前需要读取旧值。

##### 变量 a

在 B3 中被使用，且在整个流图中没有重新定义。

因此 a 在 B1～B5 的入口处均活跃。

##### 变量 b

只在 B1 中被使用。

因此仅在 B1 入口处活跃，执行完 B1 后不再活跃。

##### 变量 z

在 B3 中定义，又在 B3 中使用。

无需跨基本块保存，因此不出现在各基本块最终的 in/out 集合中。

注意：z 在 B3 内部部分程序点仍然活跃。

#### 重点与易错点

1. 活跃变量分析是反向数据流分析。
2. 分析的是变量当前保存的值是否可能在未来被使用。
3. 只要存在一条使用该值的路径，变量就是活跃的。
4. 活跃变量分析的集合元素是变量名，而不是定义点。
5. use[B] 指在定义之前被使用的变量。
6. 按本课件定义，def[B] 指在使用之前被定义的变量。
7. `x := x + 1` 需要先读取旧 x，因此 x 属于 use[B]。
8. out[B] 是所有后继基本块 in 集合的并集。
9. in[B] = use[B] ∪ (out[B] - def[B])。
10. 与到达定义分析不同，活跃变量分析初始化 in 集合。
11. 由于存在循环回边，需要迭代到不动点。
12. 某变量不在基本块入口或出口活跃，不代表它在基本块内部所有位置都不活跃。
13. 活跃变量信息是后续寄存器冲突图分析的重要基础。

### 14.3.3 冲突图、定义—使用链和网

#### 冲突图（Interference Graph）

##### 定义

冲突图的结点是待分配全局寄存器的变量。

当两个变量中的一个变量在另一个变量的定义（赋值）点处活跃时，它们之间存在一条冲突边。

冲突图是无向图：

$$
G=(V,E)
$$

其中：

- V：需要分配寄存器的变量或网。
- E：变量之间的冲突关系。

##### 冲突图的作用

用于寄存器分配，可以将寄存器分配问题转换成图着色问题。

- 每种颜色对应一个寄存器。
- 有冲突边的结点必须使用不同颜色。
- 没有冲突的结点可以使用相同颜色。

##### 活跃范围与寄存器共享

如果两个变量的活跃范围不重合，则可以共享寄存器。

例如：

- a 和 b 的活跃区间不重合。
- a 和 c 的活跃区间重合。
- b 和 c 的活跃区间重合。

对应冲突边：

$$
E=\{(a,c),(b,c)\}
$$

因此：

- a、b 可以使用同一个寄存器。
- c 必须使用另外一个寄存器。

##### 冲突图的正确性

- 多画边：可能浪费寄存器，但不会因为错误共享而破坏正确性。
- 少画边：可能将相互冲突的变量分配给同一寄存器，导致错误。

因此，构造冲突图必须保证安全性。

#### 冲突边的判定

##### 基本规则

按照课件：

**当一个变量在另一个变量的定义点处活跃时，二者发生冲突。**

注意：

仅仅因为两个变量同时出现在某个基本块入口的活跃变量集合中，并不能直接认定它们一定需要冲突边。

原因：静态活跃变量分析会合并不同执行路径的信息，可能产生保守的近似结果。

##### 课件例题

控制流：

```text
          B1: cmp k, 常量1
             /       \
  B2: i=k+1          B3: j=k+2
             \       /
          B4: cmp k, 常量2
             /       \
      B5: print i    B6: print j
             \       /
                出口
```

根据活跃变量分析：

$$
in[B_4]=\{i,j,k\}
$$

但 i、j 的定义发生在不同分支中，因此不能仅根据该入口集合就认为二者必须冲突。

课件精细分析后的冲突边：

$$
E=\{(k,i),(k,j)\}
$$

i 与 j 不连边。

##### 冲突判定算法

方法一：

1. 遍历每个变量的定义点。
2. 计算定义点处的活跃变量。
3. 根据活跃关系建立冲突边。

方法二：

1. 先计算基本块入口的活跃变量集合 in[B]。
2. 利用块入口信息分析冲突。
3. 在基本块内部进一步计算各定义点处的活跃变量。
4. 依据定义点活跃性建立冲突边。

基本块内部是线性代码，因此局部计算较方便。

#### 被多次定义的变量和冲突图

##### 问题

同一变量在不同阶段被多次定义和使用，是否必须始终使用同一个寄存器？

不一定。

##### 课件双循环例题

```text
B1:
    a := 0
    i := 0

B2:
    cmp i, 10

B3:
    a := a * i
    i := i + 1

B4:
    b := a
    i := 0

B5:
    cmp i, 100

B6:
    b := b + i
    i := i + 1
```

B3 返回 B2 构成第一个循环。

B6 返回 B5 构成第二个循环。

第一个循环使用 a、i。

第二个循环使用 b、i。

B4 中重新初始化 i：

```text
i := 0
```

因此，第一个循环中 i 的旧值不需要继续传递到第二个循环。

##### 未拆分变量 i

将 i 作为一个变量结点：

$$
V=\{a,b,i\}
$$

课件冲突图为三角形，需要三种颜色。

##### 拆分变量 i

将 i 的两个使用阶段分别记为：

$$
i_1,\quad i_2
$$

此时结点：

$$
V=\{a,b,i_1,i_2\}
$$

冲突边：

$$
E=\{(i_1,a),(a,b),(b,i_2)\}
$$

只需要两种颜色：

- R1：i1、b
- R2：a、i2

结论：

**同一个变量在不同阶段可以形成不同的寄存器分配单位，减少寄存器需求。**

为了确定这种拆分，需要使用定义—使用链和网。

#### 定义—使用链（Define-Use Chain）

##### 定义

变量的定义—使用链，是指变量的某一个定义点，以及所有可能使用该定义点产生的值的使用点所组成的链。

简称 DU 链。

一条 DU 链对应一个定义点，但可以包含多个使用点。

##### 位置表示

$$
\langle B_i,j\rangle
$$

表示基本块 Bi 中第 j 条语句。

例如：

- `<B1,1>`：B1 的第一条语句。
- `<B3,2>`：B3 的第二条语句。
- `<B6,1>`：B6 的第一条语句。

对于 `x := x + 1`：

- 右侧 x 是旧值的使用。
- 左侧 x 是新值的定义。

同一个静态语句位置可能既是使用点又是定义点。

##### 变量 a 的 DU 链

定义点：

- `<B1,1>`：a := 0
- `<B3,1>`：a := a * i

对应：

$$
L_1=\{\langle B1,1\rangle,\langle B3,1\rangle,\langle B4,1\rangle\}
$$

$$
L_2=\{\langle B3,1\rangle,\langle B3,1\rangle,\langle B4,1\rangle\}
$$

L1 从 B1 的定义出发。

L2 从 B3 的定义出发，结果可能在下一轮 B3 或之后的 B4 中使用。

##### 变量 b 的 DU 链

定义点：

- `<B4,1>`：b := a
- `<B6,1>`：b := b + i

对应：

$$
L_3=\{\langle B4,1\rangle,\langle B6,1\rangle\}
$$

$$
L_4=\{\langle B6,1\rangle,\langle B6,1\rangle\}
$$

##### 变量 i 的 DU 链

四个定义点：

- `<B1,2>`：i := 0
- `<B3,2>`：i := i + 1
- `<B4,2>`：i := 0
- `<B6,2>`：i := i + 1

对应：

$$
L_5=\{\langle B1,2\rangle,\langle B2,1\rangle,\langle B3,1\rangle,\langle B3,2\rangle\}
$$

$$
L_6=\{\langle B3,2\rangle,\langle B2,1\rangle,\langle B3,1\rangle,\langle B3,2\rangle\}
$$

$$
L_7=\{\langle B4,2\rangle,\langle B5,1\rangle,\langle B6,1\rangle,\langle B6,2\rangle\}
$$

$$
L_8=\{\langle B6,2\rangle,\langle B5,1\rangle,\langle B6,1\rangle,\langle B6,2\rangle\}
$$

其中：

- L5、L6 对应第一个循环。
- L7、L8 对应第二个循环。
- L5、L6 与 L7、L8 不具有共同的使用点。

#### 网（Web）

##### 定义

同一变量的多个定义—使用链，如果它们具有共同的使用点，则合并为同一个网。

如果某条链与已经合并的网仍有共同使用点，也要继续合并。

因此，网可以理解为相关 DU 链形成的连通分组。

##### 构造步骤

1. 为每个变量列出全部定义点。
2. 根据控制流关系，为每个定义点寻找可能到达的使用点。
3. 构造全部 DU 链。
4. 查找同一变量的 DU 链中是否存在共同使用点。
5. 合并有关联的 DU 链。
6. 重复合并，直到不能继续合并为止。
7. 每个最终分组构成一个网。

##### 课件例题

变量 a：

L1、L2 有共同使用点。

$$
\boxed{W_1=\{L_1,L_2\}}
$$

变量 b：

L3、L4 有共同使用点。

$$
\boxed{W_2=\{L_3,L_4\}}
$$

变量 i：

L5、L6 有共同使用点。

L7、L8 有共同使用点。

但前两条与后两条没有共同使用点。

因此：

$$
\boxed{W_3=\{L_5,L_6\}}
$$

$$
\boxed{W_4=\{L_7,L_8\}}
$$

得到四个网：

| 网   | 对应变量         |
| ---- | ---------------- |
| W1   | a                |
| W2   | b                |
| W3   | i1（第一个循环） |
| W4   | i2（第二个循环） |

##### 根据网构造冲突图

按照课件第 101 页的结果：

$$
V=\{W_1,W_2,W_3,W_4\}
$$

冲突边：

$$
E=\{(W_3,W_1),(W_1,W_2),(W_2,W_4)\}
$$

也就是：

```text
W3(i1) — W1(a) — W2(b) — W4(i2)
```

按照课件：

网之间存在共同的活跃点时，表示存在相应的冲突关系。

该冲突图只需要两种颜色：

- R1：W3、W2
- R2：W1、W4

即：

- R1：i1、b
- R2：a、i2

原来的变量冲突图需要三种颜色。

通过网拆分后，能够减少为两种颜色。

#### 三个概念之间的联系

##### 活跃变量分析

研究变量当前的值以后是否还会被使用。

##### 冲突图

研究哪些变量不能共享同一个寄存器。

##### 定义—使用链

研究某次变量定义所产生的值可能被哪些位置使用。

##### 网

将同一个变量中具有共同使用点的 DU 链合并，形成更精细的寄存器分配单位。

整体流程：

```text
活跃变量分析
    ↓
初始冲突图
    ↓
构造定义—使用链
    ↓
合并为网
    ↓
以网为单位重新构造冲突图
    ↓
图着色，进行寄存器分配
```

#### 重点与易错点

1. 冲突图是无向图，结点代表待分配寄存器的变量或网。
2. 有冲突边的结点不能共享寄存器。
3. 活跃范围不重合的变量可以共享寄存器。
4. 多画冲突边可能浪费寄存器，少画冲突边可能影响程序正确性。
5. 不能简单根据两个变量同属于某个 in[B] 集合就认定它们必须冲突。
6. 本课件采用的精细冲突判定是：一个变量在另一个变量的定义点处活跃。
7. 一条 DU 链对应一个定义点以及可能使用该定义值的使用点。
8. 同一变量可以拥有多条 DU 链。
9. `x := x + 1` 中，右侧是旧值使用，左侧是新值定义。
10. 同一变量的 DU 链若具有共同使用点，应合并为同一个网。
11. 两条 DU 链即使属于同一变量，没有共同使用点及间接连接，也可能属于不同的网。
12. 同一变量可以对应多个网。
13. 网可以作为新的寄存器分配单位。
14. 对变量进行网拆分后，冲突图可能需要更少的颜色。
15. 本例中变量 i 被拆为 i1、i2，寄存器需求由三种颜色降为两种。

## 14.4 循环优化

### 过程（函数）内联展开（Inlining）

#### 定义

将过程或函数的调用替换为函数体代码，从而减少函数调用时产生的额外开销。

#### 课件例题

原过程：

```text
procedure m(i, j: integer; max: integer);
begin
    if i > j then
        max := i
    else
        max := j
end
```

调用：

```text
m(k, 0, max);
```

在保持原过程参数传递语义的前提下，可展开为：

```text
if k > 0 then
    max := k
else
    max := 0
```

#### 作用

可以减少：

- 参数传递开销。
- 保存返回地址的开销。
- 函数调用及返回指令的开销。

#### 注意事项

1. 主要适用于简单、较短的函数。
2. 内联可能增加目标代码长度。
3. 需要正确处理参数传递、局部变量和返回语义。
4. 内联后可能进一步触发常量传播、死代码删除等优化。
