# 一、概述

## 1. 代码优化概述

### 1.1 定义与目标

代码优化：编译程序为了生成高质量目标程序而进行的各种加工和处理。

- 时间效率：减少程序运行时间。
- 空间效率：减少程序占用的存储容量。
- 基本原则：不能改变原有程序的语义。

### 1.2 优化的意义

- 简单的局部优化通常可以以较低代价取得明显效果。
- 进一步优化可能需要更多编译时间和分析成本。
- 循环通常占用大量执行时间，因此循环优化十分重要。
- 优化效果取决于具体程序，并非所有优化都值得实施。

### 1.3 优化的分类

#### 按是否与机器有关

1. 与机器无关的优化：通常在中间代码上进行，例如常量传播、公共子表达式删除、死代码删除。
2. 与机器有关的优化：充分利用目标机器指令系统、寄存器资源等，例如寄存器分配、指令调度。

#### 按优化范围

1. 局部优化：在单个基本块内进行。
2. 循环优化：针对循环结构进行优化。
3. 全局优化：跨越多个基本块，需要控制流和数据流分析。
4. 跨函数优化：在整个程序范围内进行分析和优化。

### 1.4 典型例题

固定循环求和：

```c
int count = 0;
for (int i = 1; i <= 100; i++)
    count += i;
```

在不存在其他副作用的情况下，可将结果直接确定为 `count = 5050`，消除循环。

### 1.5 重点与易错点

- 优化的首要前提是保持原程序语义不变。
- 代码长度变短不一定意味着运行速度更快。
- 机器相关性和优化范围是两种独立的分类标准。
- 全局优化涉及多个基本块，通常需要控制流和数据流分析。

## 14.1 基本块和流图

### 一、基本块（Basic Block）

#### 1. 定义

基本块是具有单一入口、单一出口的最大连续语句序列。

基本块的特点：

1. 基本块中的代码是连续的语句序列。
2. 控制流只能从基本块的第一条语句进入。
3. 控制流只能从基本块的最后一条语句离开。

性质：在正常执行情况下，进入基本块后将顺序执行其中的全部语句。

#### 2. 划分基本块的算法（算法14.1）

输入：四元式序列。
输出：基本块列表，每条四元式仅属于一个基本块。

**步骤一：确定入口语句（Leader）**

- 规则1：整个语句序列的第一条语句。
- 规则2：条件或无条件跳转语句的目标语句。
- 规则3：紧跟在跳转语句之后的第一条语句。

**步骤二：划分基本块**

从每个入口语句开始，直到下一个入口语句之前，所有连续语句属于同一个基本块。

记忆方法：先找入口，再按入口切分。

### 二、基本块划分例题

三地址中间代码：

```text
(1)  prod := 0
(2)  i := 1
(3)  t1 := 4 * i
(4)  t2 := a[t1]
(5)  t3 := 4 * i
(6)  t4 := b[t3]
(7)  t5 := t2 * t4
(8)  t6 := prod + t5
(9)  prod := t6
(10) t7 := i + 1
(11) i := t7
(12) if i <= 20 goto (3)
(13) ...
```

**找入口：**

- 规则1：语句(1)。
- 规则2：语句(12)跳转到(3)，故(3)是入口。
- 规则3：跳转语句(12)之后为(13)，故(13)是入口。

因此：

\[
Leader=\{1,3,13\}
\]

**划分结果：**

- B0：语句(1)～(2)
- B1：语句(3)～(12)
- B2：语句(13)

### 三、流图（Flow Graph / CFG）

#### 1. 定义

流图是一种有向图：

- 结点：基本块。
- 有向边：基本块之间可能发生的控制转移。

若存在边 B1 → B2，则：

- B1 是 B2 的前驱（Predecessor）。
- B2 是 B1 的后继（Successor）。

#### 2. 构造有向边的规则

以下任一情况成立，则建立 B1 → B2：

1. B1的最后一条语句可以通过条件或无条件跳转到B2的第一条语句。
2. B2在代码顺序上紧跟B1，且B1没有无条件跳转到其他基本块。

#### 3. 课件例题的流图

- B0 → B1：初始化后顺序进入循环。
- B1 → B1：若 i <= 20，跳回循环体。
- B1 → B2：若 i > 20，退出循环。

边集合：

\[
E=\{(B_0,B_1),(B_1,B_1),(B_1,B_2)\}
\]

### 四、重点与易错点

1. 基本块具有单一入口和单一出口。
2. 跳转目标语句和跳转后继语句都是入口语句。
3. 跳转语句本身通常是所在基本块的最后一条语句。
4. 基本块允许自环，这是循环控制流的常见结构。
5. 有向边表示可能的执行关系，而不是单纯的代码排列关系。
6. 无条件跳转之后紧跟的语句依然是划分算法规定的入口，即使它可能不可达。
7. 基本块是局部优化的基本单位，流图则是全局控制流和数据流分析的基础。

### 五、解题步骤总结

1. 编号并检查全部中间代码。
2. 按三条规则标出全部入口语句。
3. 根据入口语句切分基本块。
4. 将每个基本块画成一个结点。
5. 检查每个基本块最后一条语句的转移关系。
6. 画出跳转边、顺序执行边，形成流图。

## 14.2 基本块内优化（第一部分）

### 1. 利用代数性质（代数变换）

#### 1.1 常数合并（Constant Folding）

在编译时完成常量表达式的计算，减少运行时的运算开销。

例如：

```text
a := 5 + 6 + x
```

优化后：

```text
a := 11 + x
```

编译器也可提前完成常量表达式的类型转换，如实型变量 x：

```text
x := 3 + 1
```

可变换为：

```text
x := 4.0
```

数组地址计算也可以提前完成常量部分，只在运行时计算与下标相关的可变部分。

#### 1.2 运算强度削弱（Strength Reduction）

定义：用一种执行代价较低的运算代替另一种代价较高的运算，在保持语义不变的前提下减少运行时开销。

课件例子：

- x ** 2 → x * x
- 3 * x → x + x + x
- 8 * x → x << 3
- 4 * x → x << 2
- x / 2 → x >> 1
- x / 16 → x >> 4
- x := x + 1 → INC x
- x / 5 → x * 0.2

注意：以上转换需要满足对应的类型、溢出、舍入和目标机器语义要求，并非全部无条件等价。

区别：

- 常数合并：能在编译阶段确定的计算，提前完成。
- 运算强度削弱：运行时仍需计算，但选择更高效的运算方式。

### 2. 复写传播（Copy Propagation）

#### 2.1 定义

形如 x := y 的赋值语句称为复写语句。

由于赋值后 x 和 y 的值相同，因此满足条件时，可将后面引用 x 的地方替换为 y。

例如：

```text
x := y
u := 2 * x
v := x + 1
```

传播后：

```text
x := y
u := 2 * y
v := y + 1
```

#### 2.2 复写传播的条件

从复写语句到使用点之间：

1. 源变量 y 的值没有被修改。
2. 目标变量 x 没有被其他赋值覆盖。
3. 没有其他操作破坏 x 和 y 值相同的关系。

例如：

```text
x := y
y := 10
u := x + 1
```

不能将 u := x + 1 改为 u := y + 1，因为 y 已被重新赋值。

如果传播完成后，x 的这次赋值在后续也不再需要，则可进一步删除 x := y。

### 3. 常量传播（Constant Propagation）

当赋值语句为 x := 常量时，满足条件可将后续对 x 的引用替换为该常量。

例如：

```text
x := 3
u := 2 * x
v := x + 1
```

常量传播：

```text
x := 3
u := 2 * 3
v := 3 + 1
```

常数合并：

```text
x := 3
u := 6
v := 4
```

若后续不再需要 x，则可删除 x := 3。

临时变量消除：

```text
t1 := y / z
x := t1
```

若 t1 后续不再使用，可以化简为：

```text
x := y / z
```

### 4. 删除冗余代码（Dead Code Elimination）

#### 4.1 定义

删除对需要保留的程序结果没有影响的冗余代码、死代码或无用代码。

#### 4.2 典型情况

**情况一：无效运算**

```text
x := x + 0
x := x * 1
```

在通常整数运算语义下可删除。

**情况二：不可达代码**

```text
FLAG := TRUE
IF FLAG THEN ...
ELSE ...
```

如果 FLAG 恒为真，则 ELSE 分支不会执行，可以删除。

**情况三：调试代码**

```text
if debug then ...
```

如果 debug 为 false，相关代码可以删除。

也可以采用条件编译：

```c
#if DEBUG
    printf("debug information\n");
#endif
```

**情况四：无用赋值**

```text
x := 5
x := 8
y := x + 1
```

第一次赋值的结果从未被使用就被覆盖，因此 x := 5 可以删除。

### 5. 各优化方法的联系

| 方法         | 核心思想                           |
| ------------ | ---------------------------------- |
| 常数合并     | 提前计算已知的常量表达式           |
| 运算强度削弱 | 使用代价更低的等价运算             |
| 复写传播     | 用源变量替换目标变量的后续引用     |
| 常量传播     | 用已知常量替换变量引用             |
| 冗余代码删除 | 删除无用计算、无用赋值和不可达代码 |

多种优化可以连续使用。

例如：

```text
x := 3
u := 2 * x
v := x + 1
```

先进行常量传播，再进行常数合并。若 x 不再使用，还可删除 x := 3。

### 6. 重点与易错点

1. 代码优化必须保持程序语义不变。
2. 常数合并和常量传播不是同一概念：前者计算常量表达式，后者传播已知常量值。
3. 复写传播必须确保在传播区间内变量值的相等关系仍成立。
4. 复写传播之后，不一定能删除原来的赋值语句，需要分析后续是否仍使用其结果。
5. 运算强度削弱不是简单地将乘法换成加法，必须考虑目标机器的实际执行代价。
6. 有符号整数除法不能无条件转换为右移。
7. 删除无用赋值需要考虑跨基本块的变量使用情况。
8. 不同优化技术可以组合使用，一种优化可能触发另一种优化。
