# 高 IOPS 应用的最少磁盘数量与 RAID10 分析

## 已知条件

| 项目             | 数值        |
| ---------------- | ----------- |
| 应用可用容量需求 | 36 TB       |
| 峰值主机 IOPS    | 36,000 IOPS |
| 典型 I/O 大小    | 32 KB       |
| 单盘容量         | 960 GB      |
| 单盘平均寻道时间 | 5 ms        |
| 单盘转速         | 15,000 rpm  |
| 单盘数据传输速率 | 120 MB/s    |

以下按十进制容量计算（1 TB = 1000 GB），并假设随机 I/O、每个请求读取或写入 32 KB。单盘 IOPS 是忽略队列影响时按平均服务时间估算的理论值。

## 单盘随机 IOPS

### 平均旋转延迟

15,000 rpm 即每秒转 250 圈，一圈耗时 4 ms。平均等待半圈：

```text
平均旋转延迟 = 60,000 ms / 15,000 / 2 = 2 ms
```

### 单次 I/O 传输时间

```text
32 KB / 120 MB/s ≈ 0.267 ms
```

### 单盘平均服务时间与 IOPS

```text
平均服务时间 = 寻道时间 + 平均旋转延迟 + 传输时间
             = 5 + 2 + 0.267
             = 7.267 ms

单盘理论 IOPS = 1000 ms/s / 7.267 ms ≈ 137.6 IOPS
```

## 容量需要的磁盘数

```text
36 TB / 0.96 TB/盘 = 37.5 盘
```

盘数必须取整数，因此至少需要 **38 块盘** 才能满足 36 TB 原始容量需求。此处未计文件系统、元数据、热备盘和 RAID 冗余开销。

## IOPS 需要的磁盘数

```text
36,000 IOPS / 137.6 IOPS/盘 ≈ 261.6 盘
```

向上取整，至少需要 **262 块盘**。这是无 RAID 写惩罚、所有磁盘均匀承担负载且允许磁盘达到理论满负载时的估算。

因此，在不考虑冗余的情况下：

```text
最少磁盘数 = max(容量所需 38 块, IOPS 所需 262 块) = 262 块
```

**该应用的理论最少盘数由 IOPS 决定，约为 262 块 15K 磁盘。** 这些磁盘总原始容量约为 251.5 TB，远高于 36 TB；这是用机械盘满足高随机 IOPS 带来的容量过配。

## 吞吐带宽交叉检查

```text
应用吞吐量 = 36,000 IOPS × 32 KB ≈ 1,152 MB/s
按传输速率估算的磁盘数 = 1,152 MB/s / 120 MB/s/盘 ≈ 9.6 块
```

带宽约需 10 块盘，明显少于随机 IOPS 所需的 262 块，因此本场景的瓶颈是随机 IOPS，而不是顺序传输带宽。上面的单盘服务时间已经包含 32 KB 数据的传输时间，不能再把带宽盘数加到 IOPS 盘数上。

## 采用 RAID10 后

RAID10 将数据镜像写入两块盘，因此一次主机写入会产生两次物理磁盘写 I/O；读请求通常由镜像中的一块盘处理。RAID10 可用容量约为原始容量的一半。

### 容量下限

要提供 36 TB 可用容量，需要至少 72 TB 原始容量：

```text
72 TB / 0.96 TB/盘 = 75 盘
```

RAID10 需要镜像配对，盘数取偶数，因此容量下限为 **76 块盘**，对应约 36.48 TB 的标称可用容量。

### 性能下限取决于读写比例

题目没有给出读写比例，无法唯一确定 RAID10 的 IOPS 盘数。设读请求比例为 `r`，则写请求比例为 `1-r`：

```text
磁盘侧 IOPS = 36,000 × r + 36,000 × (1-r) × 2
             = 36,000 × (2-r)
```

计算得到的盘数向上取整，并调整为偶数；同时至少要满足 76 块的容量要求。

| 工作负载假设             | RAID10 磁盘侧 IOPS | 性能所需盘数（向上取偶数） | 加入容量下限后的盘数 |
| ------------------------ | ------------------ | -------------------------- | -------------------- |
| 全部为读请求             | 36,000             | 262                        | 262                  |
| 读写各半                 | 54,000             | 394                        | 394                  |
| 全部为写请求（保守上限） | 72,000             | 524                        | 524                  |

因此，RAID10 下的理论盘数范围约为 **262～524 块**，具体值要用实际读写比例计算。若用全写作为性能规划上限，则至少约需 **524 块盘**；容量下限 76 块不会成为主导因素。

## 方案判断与实际部署考虑

15K 机械盘按上述模型的单次服务时间约为 7.27 ms。业务对响应时间敏感时，262 块只是理论性能下限，意味着磁盘资源接近满负载；实际设计还需要按目标延迟留出 IOPS 余量，并考虑 RAID 控制器、队列深度、数据分布、重建和故障盘等影响。题目没有给出响应时间 SLA、读写比例和期望利用率，因此不能据此确定生产环境的最终盘数。

RAID10 提供镜像冗余和较简单的写入路径，但写密集工作负载的物理 I/O 需求约为主机写 IOPS 的两倍，可用容量也约减半。最终盘数应以实测读写比例和目标延迟验证。若方案允许选择其他介质，达到数百块 15K 盘才能满足的随机 IOPS 通常提示应评估 SSD 或 NVMe；是否合适还要结合预算与平台限制。
