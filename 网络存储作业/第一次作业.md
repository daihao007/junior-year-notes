# RAID5 与 RAID10 的 IOPS 计算与方案分析

## 已知条件与计算假设

- 业务总 IOPS：`7200`
- 读写比：`3:2`，即读占 60%、写占 40%
- 读 cache 命中率：`20%`
- 磁盘数量：`80` 块
- 按随机小块 I/O 估算：RAID5 写惩罚为 `4`，RAID10 写惩罚为 `2`
- 读 cache 命中只减少磁盘侧读请求；未命中的读请求由磁盘处理。假设 I/O 均匀分布到 80 块盘，不计控制器、总线、热备盘及其他瓶颈。

这里的“写惩罚”表示一次主机写请求在磁盘侧引起的 I/O 数。RAID5 的小块随机写通常需要读取旧数据和旧校验，再写入新数据和新校验，共 4 次磁盘 I/O；RAID10 需要向镜像两侧各写一次，共 2 次磁盘 I/O。

## 计算过程

### 1. 拆分业务读写 IOPS

读请求：

```text
7200 × 3 / (3 + 2) = 4320 IOPS
```

写请求：

```text
7200 × 2 / (3 + 2) = 2880 IOPS
```

读 cache 命中率为 20%，因此有 80% 的读请求需要访问磁盘：

```text
4320 × (1 - 20%) = 3456 次磁盘读 IOPS
```

### 2. RAID5

```text
磁盘侧总 IOPS = 磁盘读 IOPS + 主机写 IOPS × 写惩罚
              = 3456 + 2880 × 4
              = 14976 IOPS
```

平均分摊到 80 块盘：

```text
14976 / 80 = 187.2 IOPS/盘
```

### 3. RAID10

```text
磁盘侧总 IOPS = 磁盘读 IOPS + 主机写 IOPS × 写惩罚
              = 3456 + 2880 × 2
              = 9216 IOPS
```

平均分摊到 80 块盘：

```text
9216 / 80 = 115.2 IOPS/盘
```

## 结果汇总

| 方案   | 磁盘侧总 IOPS 需求 | 80 块盘平均每盘 IOPS 需求 |
| ------ | ------------------ | ------------------------- |
| RAID5  | 14,976 IOPS        | 187.2 IOPS/盘             |
| RAID10 | 9,216 IOPS         | 115.2 IOPS/盘             |

RAID10 的估算磁盘 IOPS 需求比 RAID5 少 `5760 IOPS`，约低 `38.5%`。反过来说，RAID5 在该模型下的磁盘 IOPS 需求约比 RAID10 高 `62.5%`。

## 哪种方案更适合

按当前给出的性能条件，**RAID10 更适合 IOPS 和响应时间优先的场景**。业务中写请求占 40%，RAID5 的小块随机写需要额外读写校验数据，导致磁盘侧负载明显增加；RAID10 的写入路径更简单，估算每盘负载也更低。

RAID5 的优势是可用容量较高。若容量和成本优先，且所选磁盘在目标延迟下能持续提供至少约 `187 IOPS/盘`，同时保留足够性能余量，RAID5 也可能满足需求。RAID10 通常只有约一半原始容量可用于数据，因此还需要结合容量预算决定。

## 适用边界

以上结果是常见 RAID 惩罚系数下的估算。它适用于随机小块 I/O；顺序整条带写、控制器写缓存、读写合并、磁盘类型和 RAID 组划分都会改变实测表现。`187.2` 和 `115.2 IOPS/盘` 是平均需求，不代表任何型号的磁盘都能在目标响应时间内达到该值。最终选型应以磁盘规格、RAID 控制器能力、容量需求和目标延迟为准。
