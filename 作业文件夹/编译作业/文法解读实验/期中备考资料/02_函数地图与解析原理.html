从源代码到输出：函数到底负责什么

以下以随附 starter 的代码为准。它来自你的语法分析版本。定位时在编辑器按 Ctrl+F 搜索函数名，完整行号表见《函数定位表》。

1. 文件分工

文件 负责什么 新增文法时通常是否要改
parser.c main、词法扫描、词法类别判断、全部递归下降函数 最常修改
token.h / token.c Token/TokenList 定义，保存和释放 token 通常不改
syntax_tree.h / syntax_tree.c 树节点、释放、后序输出语法树 新增输出规则时检查
error_list.h / error_list.c 保存错误，按行排序并写 error.txt 新错误一般直接调用 addError
CMakeLists.txt 告诉 CMake 编译哪些文件 新增 .c 文件时才需增加
config.json 原作业的平台配置 考试若有提交要求，按试卷核对

当前 token 类别用字符串存储，没有 TokenType 枚举。 新增 DOTK 不用往 token.h 增加枚举值；要保证词法产生的字符串和 parser 检查的字符串完全一致。

2. 数据结构：先认清四个“容器”

Token 的 type 是类别（如 INTTK），value 是原文（如 int），line 是源程序行号。TokenList.data 是 token 数组，size 是已经保存的个数，capacity 是已分配容量。

Parser.pos 指向下一个待解析 token，不是字符位置。Parser.tokens 指向 token 数组；Parser.errors 指向错误表；Parser.nodes 是暂存树根的栈；memoryError 表示无法继续的内存错误。

SyntaxNode 有终结符和非终结符两种。终结符指向真实 Token，非终结符如 Stmt、Exp 有 children。树中的 token 指针借用 TokenList 的数据，所以最后应先释放树，再释放 token。

ParserMark 保存三个数量：pos、nodeCount、errorCount。它代表“开始尝试某条文法前的状态”。

3. 程序主流程

main
 ├─ 打开 testfile.txt、lexer.txt
 ├─ 按字符扫描 → getWordType / getSingleCharType / getDoubleCharType
 │                → addToken → lexer.txt
 ├─ 初始化 Parser → parseCompUnit
 │                   ├─ parseDecl
 │                   ├─ parseFuncDef
 │                   └─ parseMainFuncDef → parseBlock → parseBlockItem
 │                                                     ├─ parseDecl
 │                                                     └─ parseStmt
 ├─ writeErrorOutput → error.txt
 ├─ 成功且无规定错误时 writeParserOutput → parser.txt
 └─ freeParserTrees、freeTokenList、freeErrorList

main 里词法扫描是一整段循环，没有单独的 lex() 函数。因此新增字符识别，必须同时检查该循环和 get...Type 函数。

4. 最常用的工具函数

函数 做什么 是否推进 pos
currentToken 返回当前 Token 指针，读完返回 NULL 否
checkToken 当前 token 类别是否相等 否
checkTokenAt 查看 pos + offset 的类别 否
checkNextToken 等价于 checkTokenAt(..., 1, ...) 否
advanceToken 消费当前 token，同时创建并压入终结符节点 是，成功时 +1
matchToken 类型正确才 advanceToken；否则返回 0 匹配成功才推进
expectToken 匹配则消费；缺失则记规定错误并恢复 缺失时不推进
markParser 保存当前位置、节点数量和错误数量 否
rollbackParser 释放新建树，恢复位置，并撤回此次尝试的错误 回到 mark
finishNode 把 mark 后生成的子树收进一个非终结符，压回栈 否
pushParserNode 节点栈扩容并入栈，分配失败设置 memoryError 否
freeParserTrees 释放栈中剩余树及栈数组 清理阶段
isExpStart 判断当前 token 能否开始表达式 否

返回 1 通常表示识别成功，0 表示失败。expectToken 返回 1 也可能表示已经记录缺失错误并成功恢复，不等于输入完全正确。

不要用 parser->pos++ 代替 advanceToken：前者不会创建树节点，最终输出会漏 token。不要只恢复 pos：树和错误也必须恢复。不要在 checkToken 之后又重复消费两次。

5. 用 return 1; 理解节点栈

  1. parseStmt 保存 start。
  2. matchToken 消费 return，栈中加入 RETURNTK 节点。
  3. parseExp 逐层调用 AddExp → MulExp → UnaryExp → PrimaryExp → Number，消费 1。
  4. 每层 finishNode 把刚生成的子树包装为对应的非终结符。
  5. expectToken 消费分号。
  6. finishNode(parser, start, "Stmt") 把 return、Exp、分号一起放进 Stmt。

finishNode 的名字就是输出中的 <Stmt>。不要为了方便临时命名为 DoStmt，除非试卷新增了这个非终结符并要求其输出。

语句

新增有关键字开头的语句，一般放进 parseStmt，在最后尝试赋值/表达式之前。新增声明关键字，则要检查 parseDecl、parseBlockItem、isGlobalDeclStart 等所有入口。

表达式：调用越深，结合越紧

Cond → LOrExp → LAndExp → EqExp → RelExp → AddExp → MulExp → UnaryExp → PrimaryExp
Exp  ─────────────────────────────────→ AddExp
ConstExp ─────────────────────────────→ AddExp
函数 内容
parseLOrExp ||
parseLAndExp &&
parseEqExp == !=
parseRelExp < > <= >=
parseAddExp + -
parseMulExp * / %
parseUnaryExp 一元运算、函数调用、强制转换、基本表达式
parseUnaryOp 一元 + - !
parsePrimaryExp (Exp)、LVal、Number

parseNumber 整数或字符常量
parseFuncRParams 逗号分隔的实参表达式

原文法 Exp 不是 Cond，所以不能为了让 1 < 2 出现在所有表达式位置而随意把 parseExp 改成 parseCond。新增运算符先确定试卷规定的优先级和出现范围。

AddExp → AddExp '+' MulExp | MulExp 是左递归，不能直接在 parseAddExp 开头再调 parseAddExp，否则无限递归。现有实现先读一个 MulExp，再循环读 +/- MulExp，每轮 finishNode 包装已有左子树，保持左结合，例如 8-3-1 是 (8-3)-1。

7. 词法函数与扫描循环

  • getWordType：完整读取一个标识符后查关键字表；未命中返回 IDENFR。新增 for 后，format 仍应是标识符。
  • getSingleCharType：映射 +、;、( 等单字符。
  • getDoubleCharType：映射 == != <= >= && ||。
  • main 扫描循环：处理空白、换行、字符、字符串、标识符、整数、注释、双字符和单字符。
  • addToken：复制 token 的字面值，加入动态数组。
  • initTokenList/freeTokenList：初始化/释放数组和字面值。

新增 += 时，只改 getDoubleCharType 不够：main 当前只对 = ! < > & | 尝试读取第二个字符，还必须把 + 加入候选字符集合。

新增 /= 要注意斜杠先经过注释识别；新分支不能破坏 //、/* */ 和原除法。三字符运算符不能简单塞进双字符函数，要设计最多三字符前看和未使用字符退回，遵守最长匹配。

8. 输出与错误模块

  • createTokenNode / createNonterminalNode：创建终结符/非终结符。
  • addChild：通用追加子节点工具；现有 parser 的 finishNode 直接转移子树数组，不必再调它。
  • freeSyntaxTree：递归释放树。
  • shouldOutputNonterminal：目前不输出 Decl、BType、BlockItem，但它们仍存在树中。
  • writeNode：先子节点后父节点，生成语法分析规定的后序文本。
  • writeParserOutput：管理文件开关与写文件。
  • initErrorList / addError / freeErrorList：错误表生命周期。
  • sortErrors：稳定按行号升序排序，同一行保留原记录顺序。
  • writeErrorOutput：排序并输出 行号 类别码。

9. 错误处理最容易失分的地方

旧规则：a 为单独 &/|；i 缺分号；j 缺右圆括号；k 缺右方括号。新题若增加或修改错误，按试卷的码、行号、恢复策略实现，不能自行发明错误码。

if (!expectToken(parser, "SEMICN", 'i')) {
    rollbackParser(parser, start);
    return 0;
}

输入 return 1 后下一行是 }：当前 token 为 }，expectToken 发现缺分号，记录前一个真实 token（1）的行号，保留 } 给 parseBlock 消费。它没有真的插入分号节点，也没有跳过 }。

matchToken 匹配失败只表示这条路径不成立，不会自动报错。expectToken 用在题目允许补缺恢复的位置，不能把所有 matchToken 一律替换为 expectToken，否则会接受错误结构，甚至导致不前进的死循环。

赋值与表达式共用开头，例如 a[1] = 2; 和 a[1] + 2;。当前 parseStmt 先尝试 LVal，看到 = 才进入赋值；否则 rollback 到 start，再按 Exp 重读。这也是为什么试探产生的错误必须一起撤回，否则同一个缺 ] 可能报两次。

错误恢复之后，外层仍可能彻底失败并 rollback，导致这次尝试的错误被撤销。设计新规则时必须保证剩余结构可以继续读完；不要把“调用过 addError”当成最终 error.txt 一定会有该错误。
