考场速查

开场先完成三件事

  1. 确认试卷要求的 token 类别码、输出文件名、非终结符输出规则与错误码。
  2. 备份自己的源代码，进入正确项目目录，用最小旧样例编译运行一次。
  3. 在纸上列出新规则涉及的词法、入口、子函数、恢复点，逐项修改。

PowerShell 常用命令（starter 和 examples）

gcc -Wall -Wextra -std=c11 parser.c token.c syntax_tree.c error_list.c -o compiler.exe
$LASTEXITCODE
.\compiler.exe
$LASTEXITCODE
Get-Content .\error.txt
Get-Content .\parser.txt

编译失败就停止，不能运行旧 exe。只改 testfile.txt 不用重新编译；改 .c/.h 必须编译。退出码为 0 不代替检查输出。

cmake -B build -S . -G Ninja
cmake --build build
.\build\compiler.exe

在含 testfile.txt 的项目根目录运行。使用 CLion Run 时也要设置 Working directory。cmd 查看状态用 echo %ERRORLEVEL%，看文件用 type error.txt。

修改位置口诀

要做什么 去哪里
新关键字 parser.c → getWordType
新符号 getSingleCharType / getDoubleCharType + main 扫描循环
新语句 parseStmt，放在通用赋值/表达式之前
新表达式开头 对应表达式层 + isExpStart
新类型/声明 类型与声明函数 + 所有判断声明起始的入口
输出多了/少了非终结符 finishNode 名称和次数 + shouldOutputNonterminal
缺分号/右括号/右方括号 expectToken，旧码分别 i/j/k
只想查看下一个 token checkNextToken/checkTokenAt，不能 advanceToken

四个必须记住的区别

  • checkToken：只看。matchToken：正确才吃。advanceToken：吃并建节点。
  • expectToken：缺失也可能返回成功，记录前一真实 token 行号，不吃当前 token。
  • markParser/rollbackParser：一起保存/恢复位置、树节点、错误记录。
  • finishNode：收集本规则的孩子，生成试卷规定的非终结符。

每次修改后的最小验证

正确新规则 → 新规则嵌套 → 可选段为空 → 每种规定错误 → 跨行行号 → 旧规则回归。

先看 lexer.txt：若词法不对先修词法。再看 error.txt 和 parser.txt。语法输出必须完整且顺序正确，不能只搜索到一个新关键字就判定通过。

调试构建：在 gcc 命令中加 -DPARSER_DEBUG_ENABLED=1。观察失败前 token；外层 rollback 后显示的位置可能不是原始失败位置。提交前恢复普通构建并移除自行添加的调试输出。

交卷检查

逐项核对试卷要求：源文件是否齐全、入口只有一个 main、配置是否需要提交、压缩包是否要求根目录放源码、输出名称和大小写是否一致、无旧版本混入。不要把本备考资料 ZIP 当成考试源代码提交包。
