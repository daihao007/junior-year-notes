# 第7章课后习题

## 18.1 三台计算机的服务可用性

一台计算机平均正常运行5天，也就是120小时，修复一次需要4小时，所以单机可用性为：

`A = 120 / (120 + 4) = 30 / 31 ≈ 96.7742%`

相应地，单机不可用的概率为 `p = 4 / 124 = 1 / 31`。

题目假设三台机器的故障相互独立，并且至少有一台正常运行就能提供服务。因此，只有三台同时故障时服务才不可用：

`A_service = 1 - p^3 = 1 - (1/31)^3 ≈ 99.9966%`

所以三副本服务的可用性约为99.9966%。我认为这里的关键是先明确服务的成功条件，而不是直接把三台机器的可用性相乘。如果要求三台都在线才能服务，结论就完全不同了。当然，实际系统还可能受到网络故障等因素影响。

## 18.2 多线程服务器为什么不一定满足状态机复制要求

假设两个副本的初始状态都是 `x = 1`，收到相同的两个请求：A将x加1，B将x乘2。

如果线程A先获得锁，执行顺序就是A再B：

`x = (1 + 1) × 2 = 4`

如果线程B先获得锁，执行顺序就是B再A：

`x = 1 × 2 + 1 = 3`

这两种执行顺序在多线程程序中都可能出现，即使两个副本收到请求的顺序相同，线程竞争锁的结果也不一定相同。

因此，加锁只能保证单台机器上操作互斥，不能保证不同副本按同一顺序执行。状态机复制要求相同初态和相同输入得到相同结果，所以还需要统一命令执行顺序，或者采用确定性的线程调度方式。

## 18.9 线性一致性与顺序一致性的区别

两者都要求操作能够解释为一个合法的全局顺序，但线性一致性还要求这个顺序符合操作之间的实时先后关系，而顺序一致性只要求保留每个客户端内部的程序顺序。

例如，初始 `x = 0`，客户端A执行 `W(x=1)` 并收到成功响应，此后客户端B才开始读取。如果B读到0：

- 在线性一致性下不合法，因为A的写已经完成，B之后的读必须看到1（题目中没有其他写入）。
- 在顺序一致性下可以合法，因为A和B属于不同客户端，可以把全局顺序解释为 `R(x)=0 → W(x=1)`，并没有破坏任何一个客户端内部的程序顺序。

所以我理解两者最主要的区别是：线性一致性不能打乱跨客户端的实时先后，而顺序一致性可以。因此顺序一致性通常更容易实现，不必为保证跨客户端的实时顺序付出同样严格的协调和同步成本。

## 18.14 只读副本为什么可能改善Gossip性能

假设系统有6个副本，最初全部可以处理写请求，那么6个节点都可能产生新的更新。若向量时间戳按照独立写入源设置分量，就需要记录6个分量。

如果改成2个可写副本、4个只读副本，新的更新只会从2个写入源产生，向量时间戳就可以从6维缩小到2维。这样每次传输、保存和比较版本信息的开销都会降低，更新依赖关系也更容易管理。

同时，6个副本仍然可以提供读取服务，只读副本可以分担读负载，所以不会因为写入源减少就失去多副本读的优势。不过只读副本仍然需要通过Gossip接收更新，数据也可能暂时落后；如果读取有因果依赖，还要等待相应更新同步完成。

因此，这种优化本质上是减少写入源和相关元数据的开销，代价是4个只读副本不能再直接分担写请求，而不是把所有复制通信都减少为原来的三分之一。
